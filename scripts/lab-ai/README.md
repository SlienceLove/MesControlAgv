# Windows 独立电脑试用

> 2026-10-16新增：已确认使用离子色谱电脑192.168.10.108，在仪器空闲时试用。当前先运行新包的1-Check.cmd和2-Run-Test.cmd，详见[现场运行说明](README-START.txt)及[交接](../../docs/LAB-AI-8GB-FIELD-PILOT-2026-10-16.md)。下文保留旧独立主机报表试用步骤，不把旧2K短摘要评估当作新8K流程规划性能结论。

目标：i5-13400／8 GB／UHD 730，CPU 推理。独立电脑只运行模型与测试工具，不安装或启动 MES／Adapter，不访问设备。当前交付不代表目标电脑已经部署。

## 1. 拷贝与安装

将 `ai-host` 文件夹拷到空闲电脑，例如 `D:\LabAiPilot`。如果没有 D 盘，选择有至少 8 GB 可用空间的目录；无需与中控目录相同。

从官方 [Ollama 下载页](https://ollama.com/download/windows) 或 [官方 Releases](https://github.com/ollama/ollama/releases) 获取 Windows amd64 版本。优先解压官方便携包，不需要安装开发工具；遵守该版本 Windows 系统要求。首次安装／下载模型需联网，之后推理可断网。不要使用来源不明的重打包文件。

先检查目标 Windows 版本和空闲内存。若使用安装器且其启动了 Ollama 托盘服务，应手动退出该服务后再用本脚本；不要同时启动两份。无需提前开防火墙端口。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start-AiHost.ps1 -OllamaExe .\ollama\ollama.exe -PullModel
.\Pilot.exe --benchmark .\benchmark-first
```

`OllamaExe` 指向实际解压出的可执行文件。脚本只为子进程设置环境变量，回环监听、单并发、单模型、禁止云模型、不创建开机任务；请求中指定 CPU、4 线程、2K 上下文、384 输出 token、关闭 thinking，完成卸载。模型留在磁盘，卸载只释放运行内存。下载失败后可重用已启动服务手动下载，不要再次启动占用同端口的服务。

测试目录必须不存在，以防覆盖既有证据；启动探测失败也保留已生成的样例，下次换一个目录名（如 `benchmark-second`）。测完生成 10 份带 AI 页的 Excel 和 `benchmark.json`。先打开示例工作簿核对任务状态、样品编号和已知结果，再看 AI 页；示例全部为合成数据，包含取消任务、多单位、时间缺失、错误文本、未知状态、仅测量、仅任务、提示注入文本及高精度结果，不代表真实实验建议质量已验收。退出或取消测试时用 Ctrl+C；脚本会打印其单独启动的服务 PID，停服务前核对进程身份。

## 2. 判断是否加内存

工具记录每份总耗时、Windows 最低可用内存、Ollama 进程工作集采样峰值、模型版本与摘要是否通过结构／引用检查。每份请求都在模型卸载后启动，但不是清空系统文件缓存的冷启动实验；不会自动关闭其他软件或清理系统缓存。

- 可用内存持续低于约 768 MB、明显换页／卡顿：优先考虑升至 16 GB，后续想用更大模型可考虑 32 GB。
- 内存充足但响应慢：可能主要是 CPU 推理，单加内存不保证提速；查看任务管理器并记录实际耗时。
- 摘要事实或建议不可靠：属于模型能力／提示或输入问题，不应仅靠加内存解决。升级模型也需要相同样本重新验证。
- 单份精简摘要暂以 120 秒内结束为试用目标。结构检查通过不代表内容质量通过；逐条人工核查，不能把猜测用于设备控制。

## 3. 与中控连接

有线优先，公司 Wi-Fi 可传输文件，但可能存在客户端隔离。待提供目标 IP 与授权访问方式后，只检查该目标，不扫描网段。

Ollama 无内置本地接口认证，因此本包不直接把 11434 开给局域网。推荐由公司 IT 配置 Windows OpenSSH Server、密钥登录和仅允许中控 IP 的防火墙规则，然后在中控端建立隧道（以下为格式示例，主机／账号替换为现场确认值）：

```text
ssh -N -L 127.0.0.1:11435:127.0.0.1:11434 用户名@模型电脑IP
```

首次连接人工核对 SSH 主机指纹，不关闭主机校验。不要把密码／私钥发给助手。公司不允许 SSH 时由 IT 提供经过认证的内网代理方案，不临时公开无认证端口。

新版 MES 使用 `LabReports__OllamaBaseUrl=http://127.0.0.1:11435/`、`LabReports__Model=qwen3:1.7b`；WPF 仍连接自己的 MES。模型地址来自部署配置，不接受模型输出或普通报表请求指定。配置只给独立测试实例，现场 MES 切换前须备份与确认，不自动替换当前运行服务。

中控上的 `wpf` 与 `mes` 是独立发布包，无现场数据库／配置／服务启动脚本；不能双击 MES 并假定已连接正确现场数据库。当前软件从 AI 分支基线构建，未包含其他会话尚未集成的数字孪生模型清理、工作站模板/UI 改动。先独立验收，再由集成会话统一合入。

## 4. Excel 使用规则

优先使用 `.xlsx`：记录、MES任务、统计和 AI 分工作表。编号为文本，超过 Excel 15 位有效精度的测量值以精确文本保存，程序统计保持 decimal；这类单元格要在 Excel 二次计算前明确精度处理。

导入选择“原始记录”工作表，要求标准 8 列；导出的报表附带文件指纹与行号，可重新导入。编号和时间必须为文本，时间包含时区；不接受公式／宏／外部链接，先预览再确认。5 MB／10,000 行限制，原文件与 MES 原始记录不被修改。测量记录独立导入，不自动按 MES 创建时间裁剪。

CSV 仅兼容测量明细。软件导出的 CSV 使用 `__mes_csv_text_v1` 标记及文本前缀以保护编号与避免公式执行，本软件回导时可还原；其他 CSV 仍按标准 8 列解析。请勿删除该标记列。完整查看、筛选及交换优先 Excel。
