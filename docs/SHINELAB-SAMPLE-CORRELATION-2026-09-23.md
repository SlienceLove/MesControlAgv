# DCSeq 唯一进样编号关联：最小实现

## 已确认范围

用户同意由中控生成不重复 sampleId，先本机实现，再用一条样品验证原样回传。不增加厂家协议字段，不按最近任务或时间窗口猜归属。

1. 新建 DCSeq 任务时为每一行分配通讯 sampleId，保留原始业务样品编号。编号为 9 位十进制字符串，位于有符号 32 位整数范围内；用加密随机数生成并检查持久化登记表，数据库全局唯一索引是最终防重约束。冲突时不提交任务或发送报文，可按同 taskUuid 重试。该格式仍需厂家客户端实测，不假设无限字符串支持。
2. 任务、行映射和用于下发的 Config 同一次数据库提交。重启后继续使用已保存映射；同 taskUuid 同请求重试返回原编号，真正复测必须新建 taskUuid。运行库和登记表不可清空/回滚后继续复用旧编号；其他中控实例需共享登记库或分配独立编号域。
3. 只有中控已尝试发送 Config 的映射才参与 sampleId 自动关联；创建任务、预览不会发送或启用关联。设备不符、显式任务与样品映射冲突、未知编号不自动归档。
4. Result、SampleFinish、TaskFinish、EndMission 及样品级故障按映射保留到对应任务行；原始证据继续全量留存。任务详情增加行映射和结果汇总，保留现有接口字段。直接设备 Config 接口仍属于未托管诊断入口，不自动登记任务。
5. 不同样品分别存结果，不覆盖其他行。重复 Result 只增加原始证据，不重复任务观察；同一进样编号返回不同结果则保留原结果、标记冲突待核对，不静默覆盖。
6. 结果汇总区分无结果、部分结果、全部结果及冲突。全部结果仅表示结果收齐，不自动标记正常完成；停止/失败语义另行验证。
7. 旧 Rike 和已有未托管任务不重写编号、不回填猜测映射。已收到的手工样品 8 仍作为联调证据。

## 实施与验证顺序

- 新增映射表、兼容旧库的补表逻辑、任务详情和已分配编号的只读 Config 预览。
- 测试编号唯一、重启/重复创建不变、多样品结果、错误设备/冲突标识、未发送任务不关联、重复与结果冲突、旧协议兼容。
- 隔离 TCP 模拟必须使用真实 Config 发送路径和保存的编号，验证客户端仅返回 sampleId 时结果能进入对应任务。
- 完成回归后生成独立发布包。先通知用户再切换服务或发送现场 Config，不能因为 Config 接受就认为创建成功。
- 现场只创建一条明确的测试行；用户核对 AQ 编号、样品位置、处理方法和勾选项后，再执行样品测试。Config 自动勾选且运行中可能自动执行，发送前必须确认状态及目标序列。
- 若 AQ 改写/拒绝编号，停止按 sampleId 自动闭环的现场验收，记录实际行为并请厂家原样回传 sampleId 或扩展 clientSampleId；不继续猜匹配。
