> 控制器为 `192.168.1.2`，不是本文件早期示意中的 `.100`。笔记本以太网

> 控制权端口 `19207`、其他 API（含 DO）端口 `19210` 均已由现场软件/配置

## 架构原则确认

### ✅ 正确的架构：中控统一调度

```
┌─────────────────────────────────────┐
│         中控系统 (MES)              │
│  - 任务编排                         │
│  - 设备协调                         │
│  - 状态监控                         │
│  - 异常处理                         │
└──────┬─────────┬─────────┬──────────┘
       │         │         │
       ▼         ▼         ▼
   ┌──────┐  ┌──────┐  ┌──────┐
   │ AGV  │  │机械臂│  │ 视觉 │
   │控制器│  │控制器│  │ 系统 │
   └──────┘  └──────┘  └──────┘
     AGV 小车内部
```

**优势**：
- ✅ 中控拥有完整控制权
- ✅ 所有操作可审计追溯
- ✅ AGV 关机不影响视觉系统独立测试
- ✅ 可以灵活调整工作流程
- ✅ 便于异常恢复和人工介入

### ❌ 错误的架构：视觉直接控制机械臂

```
         ┌─────────┐
         │  中控   │ (只能监控，无法干预)
         └─────────┘
              │
              ▼
         ┌──────┐
         │ AGV  │
         └──────┘
           AGV 小车内部
              │
              ▼
         ┌──────┐  ──直接控制──>  ┌──────┐
         │ 视觉 │                 │机械臂│
         └──────┘  <──状态反馈──  └──────┘
```

**问题**：
- ❌ 中控无法实时监控机械臂状态
- ❌ AGV 关机后视觉和机械臂失联
- ❌ 无法记录完整的操作日志
- ❌ 难以处理异常情况
- ❌ 无法手动干预或测试

## 网络拓扑设计

### 推荐方案：中控直连所有设备

```
办公室/控制室
┌─────────────────────────────────────────┐
│  中控 PC (192.168.1.10)                 │
│  - MES 服务                             │
│  - Adapter 服务                         │
│  - WPF 操作界面                         │
└───────────────┬─────────────────────────┘
                │
        ┌───────┴─────────┐
        │   交换机/路由器  │
        └───────┬─────────┘
                │
    ┌───────────┼───────────────┐
    │           │               │
    ▼           ▼               ▼
┌────────┐  ┌────────┐      ┌──────────────────┐
│  AGV   │  │ 机械臂 │      │   视觉工控机     │
│ 控制器 │  │ 控制器 │      │                  │
│        │  │        │      │  (可能是独立PC   │
│192.168 │  │192.168 │      │   或嵌入式设备)  │
│.1.2    │  │.1.102  │      │  192.168.1.101   │
└────────┘  └────────┘      └──────────────────┘
  (移动)     (固定在AGV上)    (固定在AGV上或独立)
```

**关键点**：
1. 所有设备都在同一网段
2. 中控可以直接访问每个设备的 IP
3. 设备之间不直接通信（除非必要的硬件触发）
4. AGV 移动时通过 WiFi 保持网络连接

### 网络配置建议

```yaml
设备分配表:
  中控PC:
    IP: 192.168.1.10
    角色: 主控
    
  AGV控制器:
    IP: 192.168.1.2
    端口: 19204 (状态), 19206 (命令), 19207 (控制), 19210 (其他/DO)
    连接方式: WiFi (移动) + 有线 (充电桩)
    
  机械臂控制器:
    IP: 192.168.1.102
    端口: 30004 (AUBO JSON-RPC，需复核连通性)
    连接方式: 跟随 AGV (通过 AGV 的网络)
    
  视觉工控机:
    IP: 192.168.1.101
    端口: 8081 (推测，待确认)
    连接方式: 跟随 AGV (通过 AGV 的网络)
    
网络要求:
  - 带宽: 至少 100Mbps (视觉图像传输需要)
  - 延迟: < 50ms (实时控制要求)
  - WiFi: 2.4G/5G 双频，覆盖整个工作区域
  - 备用: 考虑 4G/5G 作为备用链路
```

## 状态监控与异常处理

### 中控实时监控内容

```csharp
public sealed class DeviceMonitor
{
    // 每秒更新一次
    public async Task MonitorAllDevicesAsync(CancellationToken cancellationToken)
    {
        while (!cancellationToken.IsCancellationRequested)
        {
            // 1. AGV 状态
            var agvStatus = await _agvDriver.GetSnapshotAsync("AGV-01", cancellationToken);
            // - 位置、电量、任务状态、错误
            
            // 2. 机械臂状态
            var armStatus = await _armDriver.GetStatusAsync(cancellationToken);
            // - 当前位姿、是否持有物体、错误
            
            // 3. 视觉状态
            var visionStatus = await _visionDriver.GetStatusAsync(cancellationToken);
            // - 连接状态、相机状态
            
            // 4. 更新 WPF 界面
            await UpdateDashboardAsync(agvStatus, armStatus, visionStatus);
            
            await Task.Delay(1000, cancellationToken);
        }
    }
}
```

### 异常处理策略

| 异常类型 | 检测方式 | 处理策略 |
|---------|---------|---------|
| **AGV 通信超时** | 3秒未响应 | 暂停任务，等待恢复或人工介入 |
| **AGV 导航失败** | 状态返回 Failed | 重试1次，失败则任务标记为 Failed |
| **机械臂通信超时** | 5秒未响应 | 尝试急停，任务标记为 Error |
| **机械臂碰撞检测** | 力矩异常 | 立即停止，回退到安全位置 |
| **视觉识别失败** | confidence < 0.8 | 重新拍照2次，仍失败则报警 |
| **视觉未找到物体** | found = false | 调整位置后重试，或人工确认 |
| **抓取失败** | gripper 未闭合 | 重试1次，失败则任务暂停 |
| **网络断开** | WiFi 断连 | 所有设备进入安全状态，等待恢复 |
