# 离子色谱接口开发会议简报

## 一、当前结论

离子色谱的基础通讯已经具备实验验证条件。最新方案是不再由中控直接打开串口，而是由 ShineLab 负责设备和串口控制，中控通过 TCP 接收状态并下发业务任务。

最新链路：

```text
ShineLab（TCP Client，负责串口） ──TCP── 中控 TCP Server / MES ── WPF
```

目前已确认：

- D160+：COM4、115200 8N1、Modbus RTU，只读链路已完成现场验证；
- SHA-18i：COM3 的状态读取、方法块下发和自动进样报文已有厂家协议及现场抓包证据；
- 软件已增加中控侧 ShineLab TCP Server、状态缓存和 WPF 设备状态查询页面；
- WPF 不再直接连接 SHA-18i/D160+ 串口，只显示 ShineLab 推送的在线、任务和报警状态；
- ShineLab Client 和中控 Server 的现场联调尚未完成。

## 二、当前困境

1. **TCP 角色和端口需要落地**：ShineLab Client 的连接配置、中控 Server 监听端口和防火墙策略需要确认。
2. **推送字段需要固定**：在线、当前任务、样品、通道、阶段、进度、报警和结果字段需要形成 SHA18i 约定。
3. **任务闭环需要定义**：Config、Command、响应、SampleFinish、TaskFinish、TaskError、Result 的关联和错误码需要明确。
4. **重连和状态恢复需要验证**：断线后 ShineLab 必须自动重连并重新 Certification，中控不能误判任务结果。
5. **方法和检测方式需要区分**：进样方法、检测方式和结果处理方法必须分字段传递。
6. **现场网络尚未统一**：实验先用两台电脑直连网线，生产切换到交换机或现场 WiFi 路由。

## 三、总部需要提供的帮助

### ShineLab 厂家/技术支持

- 按确定的角色提供 ShineLab 常驻 TCP Client 版本；
- 确认 SHA-18i 型号、固件、串口参数和设备编码；
- 提供 Certification、UpdateInfo、Config、Command 和结果/异常上报的完整示例；
- 明确方法、检测方式、通道、样品位置、停止和清洗字段；
- 提供自动重连、重复任务去重和设备忙时的返回规则；
- 提供一次远程或现场见证，完成“配置→启动→完成→结果”的动作确认。

### 项目/基础设施支持

- 提供中控 Server 的开发/测试 IP、端口和防火墙配置；
- 协调 ShineLab 常驻运行、测试设备和现场联调时间；
- 提供实验样品、测试方法和现场见证人员；
- 指定总部技术负责人，及时确认协议问题和现场异常；
- 明确生产网络采用交换机还是 WiFi，以及固定 IP/DHCP 方案。

## 四、按时间划分的开发路线

### 路线 A：最快联调，1～2 天

目标：证明 ShineLab 可以连接中控并稳定推送状态。

1. 两台电脑直连网线；
2. ShineLab 配置中控 Server IP/端口并开机常驻；
3. 完成 Certification 和 UpdateInfo 推送；
4. WPF 设备状态查询页显示在线/离线和任务状态；
5. 保存连接日志和 JSON 报文。

交付物：连接、心跳和状态推送的完整通讯证据和问题清单。

### 路线 B：短期实验闭环，1～2 周

目标：形成可重复的实验任务流程。

- 完成 Config、Command 和响应；
- 完成单样品启动、SampleFinish、TaskFinish、TaskError、Result；
- 增加样品编号、通道、位置、进样方法和检测方式字段；
- 增加任务日志、重连、重复消息和人工恢复；
- 保持 ShineLab 独占设备串口，中控不再直连串口。

交付物：固定方法、固定样品、可重复执行的实验版本。

### 路线 C：生产化，3～6 周

目标：切换到正式生产流程。

- WPF→MES→CentralTcpServer→ShineLab 统一任务链路；
- 任务持久化、幂等、审计、结果文件关联和断线恢复；
- 完成交换机/WiFi 网络部署和网关自动启动；
- 完成 ShineLab 与中控控制权切换流程；
- 完成连续稳定性、异常恢复和现场验收。

交付物：可纳入生产任务调度的正式接口。

## 五、会议需要形成的决议

1. 是否确认 ShineLab Client、中控 Server 的角色和端口；
2. 是否批准第一轮连接、状态推送和单样品任务联调；
3. ShineLab 何时提供可配置的 Client 测试版本和完整报文；
4. 厂家/总部何时提供字段、错误码、停止语义和结果接口确认；
5. 确定现场见证人员、测试时间和验收标准。

## 六、会议口头汇报稿

目前 D160+ 和 SHA-18i 的基础通讯已经确认，协议和现场抓包能够对应上。最新方案是不再由中控直接连接串口，而是由 ShineLab 负责设备控制，ShineLab 作为 TCP Client 常驻运行并向中控 Server 推送状态，中控通过 TCP 下发业务任务。当前主要卡点是 ShineLab Client 测试版本、TCP 角色/端口、状态和任务字段、重连恢复以及结果接口。希望总部协调厂家提供完整协议和可联调版本，安排现场见证及网络、设备条件支持。时间上建议分三步：1～2 天完成连接和状态推送联调，1～2 周完成单样品任务闭环，3～6 周完成 MES、生产网络和正式验收。
