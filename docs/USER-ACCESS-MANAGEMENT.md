# 本地登录与用户权限首版

已确认：本地账号、管理员/操作员/只读三种固定角色，蓝白 WPF 登录页、用户管理、修改密码和退出登录。客户演示使用独立端口、模拟设备及数据库，不接管现场进程。

实现计划：账号与会话契约 → SQLite 账号库和服务端访问控制 → 登录/用户管理窗口 → 主界面身份和权限 → 隔离演示启动器 → 回归与权限绕过检查。

认证由 MES 校验。密码使用 ASP.NET Core PasswordHasher（PBKDF2），仅保存哈希；随机会话令牌仅客户端内存保存，服务器仅存令牌 SHA256。会话八小时有效；登出、改密、停用和角色变更使有关会话失效。连续五次密码错误锁定五分钟；初始化管理员密码通过进程环境传入，不提交固定口令。不能停用或降级最后一个管理员。

权限：所有 MES 业务接口要求会话；只读账号只能 GET/HEAD；操作员可操作任务、实验及物料，不能管理用户、系统配置或直接设备调试。未知写入接口默认仅管理员。权限不替代现有物理准入。业务 JSON 操作人由服务端登录身份覆盖，不采信客户端自行填写的 actor/operatorName。

演示通过 `Access:Enabled=true` 显式启用；现有未迁移现场实例不改变行为，不声称它们已经受到认证保护。独立账号数据库与业务数据库分开。管理员角色只授权 MES，不开放 Adapter/厂家直连接口；正式联网部署需由网络隔离和服务身份另行保护网关，使用 HTTPS，不以本地 HTTP 演示作为生产安全验收。

界面预期：登录后 KPI；右上角账号、角色、改密和退出；管理员可打开用户管理（账号、姓名、角色、状态、最近登录）。退出登录只撤销会话和关闭业务界面，不停止后台服务或任务。角色决定导航/操作控件，同时服务端拒绝越权调用。

验证：错误密码、账户锁定、无令牌401、只读写入403、操作员配置403、管理员用户管理、最后管理员保护、会话撤销、身份不可伪造、旧配置回归、WPF 登录窗口布局及隔离演示。第一版不做 SSO、组织架构、自定义权限树、网络部署或真实设备动作。
