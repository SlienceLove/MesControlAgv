# 锐克模块 Command 严格模板设计 · 2026-09-11

## 目标

让中控 MES 对锐克模块发送的 `Command` 与厂商确认模板完全一致，同时保留
MES 自己的任务审计和响应关联能力。当前阶段只做本地序列化和自动化测试，不
自动向现场设备发送控制报文。

## 线上格式

TCP 连接沿用已验证的 LF-JSON 分帧。`Command` 的 JSON 外壳由连接管理器补充
唯一 `strID`、`strMethod=Command` 和目标 `equipmentCode`。业务 body 严格只含：

```json
{
  "chan": "A",
  "action": 0
}
```

动作码目前按锐克模板记录为 `0`（启动取样/进样）、`2`（停止取样）、`7`（清洗）。
不在允许集合内的动作码在本地请求校验阶段拒绝。

## 本地关联

`TaskUuid`、样品号、样品名、检测方法和清洗时间继续保留在 MES 请求对象、任务
数据库和事件审计中，但不放入锐克 `Command.body`。响应仍通过外壳 `strID` 与
连接管理器关联，再由任务服务记录结果。

## 变更范围

1. 新增可复用的 `ShineLabCommandPayloadBuilder`，负责严格 body 构造和动作码校验。
2. `ShineLabCommandService` 使用该 builder，不再发送历史扩展字段。
3. 增加动作码 `0/2/7`、拒绝未知动作、body 字段精确集合的离线测试。
4. 更新锐克交接记录，标记截图模板已经由现场确认适用于锐克模块。

## 安全边界

- 不改变 TCP 监听、设备识别或只读状态处理。
- 不在构建和测试阶段启动真实 `Config`/`Command` 下发。
- 真实进样仍需先完成单条 Config 预检，并由现场人员明确授权后才执行。
