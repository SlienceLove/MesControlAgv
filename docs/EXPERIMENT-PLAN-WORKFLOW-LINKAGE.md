# 实验方案、固定流程模板与设备运行时间轴

> 分支：`feature/wpf-ui-layout-optimization`
> 状态：模板目录和方案编排阶段 1 已实现；复合运行时已完成无设备状态机基础，持久化编排仍待后续阶段实现
> 安全边界：本设计不自动授权实体设备写入，不绕过现有运行准入和 `Unknown` 处理。

## 1. 当前缺口

现有实现中，`ExperimentPlan` 只有一组 `WorkflowId/WorkflowVersion`，因此一个方案只能绑定一个流程版本。任务排程可以选择已发布方案并创建任务，但时间轴只表达资源预留和运行租约，不能表达“方案中的第几段流程在什么时间使用哪台设备”。

这会造成三个问题：

1. 流程管理、实验方案和排程之间只能通过一个字符串/版本间接关联。
2. 方案无法复用多个已经验证过的固定流程模板。
3. 排程人员无法区分同一任务在不同时间段的搬运、检测、清洗或人工确认阶段。

## 2. 目标职责划分

```text
流程管理（模板库）
  发布、验证、版本固定、能力/资源要求
              |
              v
实验方案（编排）
  选择模板版本、定义顺序、参数覆盖、预计时长
              |
              v
实验任务 / 排程
  固定方案版本、计算时间段、分配资源、检查冲突
              |
              v
复合运行时
  按步骤创建运行上下文、逐步执行、记录设备活动
              |
              v
运行时间轴
  每台设备/资源：计划段、实际段、状态、异常和审计
```

### 2.1 流程管理：只维护经过验证的模板

- `WorkflowVersion` 是不可变版本；只有 `Validated + Published` 版本才能进入方案。
- 模板定义节点、边、设备能力和安全策略，不承载某个样品批次的计划时间。
- `IsPreset` 可以作为“系统模板/现场模板”的展示标识，但发布资格仍由版本校验和能力检查决定。

### 2.2 实验方案：自由编排模板顺序

方案版本新增有序 `WorkflowSteps`：

| 字段 | 作用 |
| --- | --- |
| `StepId` | 方案内稳定步骤身份 |
| `Order` | 执行顺序 |
| `WorkflowId/WorkflowVersion` | 指向不可变、已发布流程版本 |
| `Name` | 方案中的业务步骤名称 |
| `EstimatedDurationMinutes` | 排程切分和资源估算使用的预计时长，不能当作实际时长 |
| `Parameters` | 该步骤允许的结构化参数覆盖 |

旧的 `WorkflowId/WorkflowVersion` 字段暂时保留为兼容字段，始终映射到第一步。读取旧数据时自动生成一个步骤；写入新数据时同时保存步骤数组和第一步兼容字段。

### 2.3 排程：先做计划时间轴，再叠加实际状态

排程时应检查：

- 所有模板版本仍为已发布状态。
- 步骤顺序、步骤 ID 和预计时长有效。
- 步骤所需资源与方案资源要求一致。
- 每个资源在计划窗口内没有容量冲突。

时间轴至少分两层：

1. **计划层**：根据步骤预计时长切分 `PlannedStart/PlannedEnd`，显示样品批次、步骤名称和计划/阻塞状态。
2. **实际层**：运行后根据节点执行、设备操作和资源租约的真实时间显示 `ActualStart/ActualEnd`、设备状态和异常。

计划层不能冒充实际执行；没有实际证据时显示“未开始/未采集”，而不是补齐一个看似准确的时间段。

## 3. 已实现的第一段

- Contracts 增加 `ExperimentPlanWorkflowStep` 和 `WorkflowSteps`。
- `ExperimentPlanRecord`、`ExperimentJobRecord` 和 SQLite 启动升级增加 `WorkflowStepsJson`。
- 旧方案读取自动兼容为一个步骤；创建任务时保存方案步骤快照。
- 实验方案页增加“执行流程”标签，可添加、删除、上移、下移固定流程模板并填写预计时长。
- 任务排程页显示选中任务的执行流程摘要。
- 有预计时长的多步骤任务会在资源时间轴上切成有序步骤块。
- MES 排程查询会把已有节点执行/设备操作投影为实际设备活动块，显示实际状态、时间和错误摘要。
- 实验方案模板下拉投影每个已发布版本的能力、资源、明确的预计时长和最近验证信息；未声明的时长保持“未配置”，不会用超时值臆测。
- 方案校验问题按 `workflowSteps[n]` 定位到具体步骤，并即时提示多步骤方案缺失预计时长或引用不可用版本。
- Contracts 增加 `ExperimentRun` / `ExperimentStepRun` 外层运行快照；Domain 状态机按稳定 `StepId/StepRunId` 逐步推进，不允许跳步、活动步骤重复启动或在 Unknown 状态静默取消。
- MES 以 `ExperimentRuns` 持久化外层快照，提供显式 `/api/experiment-runs/prepare` 与只读查询接口；准备阶段不创建子工作流、不写入设备。
- WPF 流程运行监控按实验任务读取复合快照，显示每个方案步骤的状态、子流程关联和时间/异常；运行 ID 继续仅保留在高级入口。
- 对已排程多步骤任务提供带操作者原因和二次确认的“建立复合运行”入口；该入口只准备外层快照，不触发设备操作。
- 复合运行时尚未完成时，多步骤任务的运行准入返回明确的 `EXP-COMPOSITE-WORKFLOW-NOT-SUPPORTED`，禁止误执行第一步后结束。

## 4. 后续实施阶段

### 阶段 1：模板目录和方案编排（首轮完成）

- [x] 增加“仅系统/已验证模板”筛选；模板下拉继续显示“系统/已验证模板”或“已发布流程”状态。
- [x] 筛选投影不改变当前步骤选择；当前方案引用的非筛选项仍会保留在下拉中。
- [x] 旧方案引用但目录中已不存在的流程版本继续保留，并明确标记为“已引用但不可用”。
- [x] 为每个模板显示能力、资源、预计时长和最近验证信息。
- [x] 方案校验增加步骤级问题定位和时长缺失提示。

### 阶段 2：复合运行时

- [x] 新增 `ExperimentRun` / `ExperimentStepRun` 运行快照，固定 `PlanId/PlanVersion/StepId/WorkflowVersion`。
- [x] 完成设备无关的启动、步骤边界、暂停/恢复、取消和 Unknown 人工核销状态机。
- [x] 持久化 Prepared 外层快照并提供幂等准备/只读查询 API；准备请求不创建子工作流或设备操作。
- [x] 监控页按任务展示复合步骤状态；没有子流程上下文时显示明确占位，不伪造节点或设备证据。
- 每一步创建独立的节点执行上下文，步骤完成后才允许进入下一步。
- 暂停、取消、未知结果和恢复必须在步骤边界和设备操作边界分别留痕。
- 复合运行时完成并通过模拟器验收前，继续拒绝多步骤实体运行准入。

### 阶段 3：实际设备活动时间轴（第一段完成）

- [x] 新增只读 `ExperimentScheduleActivity` 投影：任务、步骤、节点、设备、计划时间、实际时间、状态和错误摘要。
- [x] MES 查询服务从节点执行、设备操作生成活动投影；WPF 不直接读取设备协议。
- [x] 排程资源泳道显示实际设备活动块，并与计划预留/运行租约使用不同视觉语义。
- [x] 计划步骤和实际活动使用稳定的步骤字段；WPF 选中活动块后显示设备、状态、实际时间和异常摘要。
- [x] 缺失设备证据的活动统一落入“未分配资源”泳道，不把活动猜测归到第一台请求设备。
- [x] 泳道按实际重叠块动态扩展轨道，避免多个计划/租约/活动互相覆盖。
- [x] 流程运行监控优先按实验任务和方案步骤选择，运行 ID 仅保留在高级折叠入口。
- [x] 运行监控继续保留独立全屏窗口；复合方案尚未建立步骤运行上下文时显示明确等待状态。
- [ ] 复合运行时为每个方案步骤补齐稳定的 `WorkflowStepId` 和实际设备活动关联。
- [ ] 设备泳道支持“计划 / 实际 / 当前”三种视觉层，点击活动块可跳到步骤详情和审计证据。

### 阶段 4：资源能力和排程估算

- 从模板节点能力目录推导最小资源要求，方案只允许补充或收紧约束，不得绕过能力门禁。
- 根据历史运行数据生成预计时长建议，但必须由操作员确认后写入方案。
- 计划冲突、实际超时和资源租约冲突分别显示，避免混成一种“失败”。

## 5. 验收标准

- [x] 一个旧单流程方案读取后仍可正常查询、编辑、校验和发布。
- [x] 一个新方案可以配置至少两个固定流程模板并调整顺序。
- [x] 方案和任务响应中包含步骤顺序及模板版本快照。
- [x] 排程时间轴在预计时长完整时显示步骤级计划块。
- [x] 缺失步骤 ID 的旧客户端输入使用确定性 ID，重试和读取不会改变步骤身份。
- [x] 多步骤运行时未完成前不会静默执行第一步。
- [ ] 复合运行时可以逐步骤恢复并处理未知结果。
- [x] 运行时间轴显示现有单流程运行的设备活动和状态证据。
- [ ] 运行时间轴覆盖复合方案的每个步骤和每个设备。
- [ ] 计划与实际时间轴可以同时查看并区分颜色/文字语义。
