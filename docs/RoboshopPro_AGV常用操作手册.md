# Roboshop Pro AGV 常用操作手册（现场 SOP）

> **适用对象**：现场工程师、调试工程师、设备维护人员、MES/WMS/调度系统联调人员  
> **文档版本**：v1.0  
> **编制日期**：2026-08-05  
> **软件名称写法**：现场资料中可能写作 **Roboshop Pro**、**RoboShop Pro** 或 **RoboshopPro**，本文按“Roboshop Pro”统称。  
> **重要声明**：不同 Roboshop Pro 版本、AGV 车型、导航方式、权限和调度系统的界面、字段、单位及可用功能可能不同。本文只给出现场 SOP 和核查方法，**所有菜单名、字段名、单位、默认值和放行条件，必须以当前界面字段、设备手册、项目批准参数和现场安全规则为准**。

---

## 1. 目的、适用范围与版本差异

### 1.1 目的

用于指导工程师完成以下闭环：

> **连接 → 备份 → 地图/点/路径配置 → 速度与安全参数确认 → 空载测试 → 带载验证 → 发布/下发 → 运行观察 → 必要时安全回滚**

本文重点覆盖：

- 地图、站点、位置点、路径和动作/任务的配置；
- 直线/旋转运动速度、加减速、载荷和安全区域等参数的核查；
- 单机导航与调度系统联调；
- 充电站、停靠点等功能（当前版本支持时）；
- 常见报警、诊断、变更记录和回滚。

### 1.2 适用范围

适用于使用 Roboshop Pro 进行建图、机器人模型编辑、站点/路径配置、单机导航测试，或与 RDS、MES、WMS 等上层系统联调的 AGV 项目。

不替代以下文件：

- AGV 机器人本体、激光雷达、二维码/反光板、充电机和安全控制器的设备手册；
- 当前项目批准的风险评估、速度限制、交通规则和安全区域图；
- 现场电气、机械、消防和人员安全作业规程；
- 当前版本 Roboshop Pro、RDS、MES/WMS 的正式发行说明和配置基线。

### 1.3 版本差异声明

1. **以当前界面字段和设备手册为准**：本文不假设固定菜单路径，不把某一版本的 UI 标签当作通用菜单名。
2. “保存”“发布”“下发”“同步”“应用”等操作在不同版本中可能是一个按钮，也可能是多个步骤；必须确认操作对象是本地工程、AGV 本体还是调度系统。
3. Roboshop Pro 的单机导航地图（现场资料中可能称 **SMap** 或类似名称）与 RDS/调度系统使用的布局图、交通规划图可能不是同一文件。**不得把单机地图和调度地图混用或覆盖。**
4. 公开的旧版 Roboshop 资料中曾出现 `Direction`、`Movestyle`、`maxspeed`、`maxacc`、`maxrot`、`maxrotacc`、`reachdist`、`reachangle`、`slowdowndist`、`blockdist` 等字段；这些仅作为历史公开资料中的概念参考，字段可能已更名、拆分、合并或不再存在，**禁止直接按字段名或历史数值硬编码**。
5. 本文中的数值只用于说明记录方式或测试起始方式，并均标明“示例/起始值，不是通用安全值”。它们不能作为现场放行标准。

## 3. 术语与对象模型

### 3.1 配置层与运行层

必须将两层分开管理：

| 层级 | 主要对象 | 作用 | 变更后主要验证 |
|---|---|---|---|
| **配置层** | 地图、地图图层、站点、位置点、路径、方向、运动参数、禁行/减速/安全区域、充电/停靠配置 | 描述 AGV “在哪里走、怎么走、以什么限制走” | 定位、连通性、方向、路径可达性、避障/减速、安全边界、版本一致性 |
| **运行层** | 任务、路线、动作、调度、队列、AGV 状态、报警、人工确认、执行日志 | 描述 AGV “现在执行什么、由谁调度、执行到哪一步” | 任务下发、状态回传、到站判定、动作完成、异常恢复、取消/重试幂等性 |

**原则**：

- 配置层未验证，不得用运行层反复试错；
- 运行层报警不一定是路径问题，先区分“配置错误、通信错误、机械/安全触发、调度逻辑错误”；
- 修改配置后要记录配置版本；修改任务或调度规则后要记录运行层版本/发布批次。

### 3.2 对象定义

| 对象 | 说明 | 现场要点 |
|---|---|---|
| 地图 | AGV 定位与导航使用的空间数据及相关图层 | 确认是否为单机地图/SMap，避免与调度布局图混淆 |
| 站点 | 业务或交通意义上的目标位置，如取货、放货、充电站 | 一个站点可能包含多个位置点或多个朝向 |
| 位置点 | 地图中的具体坐标、朝向、到站判定区域或停靠姿态 | 记录坐标系、朝向、容差和到站判定方式 |
| 路径 | 连接位置点的可行驶线段/曲线及其运动属性 | 检查方向、连通性、转弯空间和限制区 |
| 动作 | 到站后执行的业务/机械动作，如等待、取放货、顶升 | 由当前版本支持的动作类型为准 |
| 任务/路线 | 运行层对一组位置点和动作的编排 | 记录创建来源、任务 ID、状态和结果 |
| 安全区域 | 禁行、减速、停障、人员/设备保护等区域 | 以安全负责人批准的区域和策略为准 |
| 发布/下发 | 将配置应用于本地工程、AGV 或调度系统的过程 | 先备份、再小范围验证、最后扩大范围 |

## 4. 前置条件与安全要求

### 4.1 前置条件

- [ ] 已完成现场风险评估，明确人员、叉车、托盘、货架、门禁和交叉口风险。
- [ ] 已确定测试区域并设置警戒线、告示和人员管控。
- [ ] AGV 电量、机械状态、轮胎/驱动、载荷机构、急停和安全雷达状态正常。
- [ ] 工程电脑时间、网络、账号权限和存储空间正常。
- [ ] 已获取当前地图、点、路径、参数、调度配置和任务模板的可恢复备份。
- [ ] 已确认空载测试、带载测试、障碍物测试和放行的负责人。
- [ ] 现场人员知道急停位置、复位条件、手动接管方式和故障升级联系人。

### 4.2 安全规则

1. 配置前先让 AGV 进入安全状态；需要近距离作业时执行现场规定的停机、断能或挂牌上锁流程。
2. 首次下发、地图变更、路径变更、速度变更后，优先使用低风险区域、低速、空载和单车测试。
3. 不以“软件显示无报警”替代机械、电气和人员安全确认。
4. 禁止在人员、叉车或其他移动设备未隔离时直接运行新路径。
5. 急停解除、报警复位、手动模式切回自动模式，都必须由授权人员按现场规程执行。
6. 发现定位跳变、路径越界、异常加速、异常旋转、到站冲过点、障碍不停车或停止后不恢复时，立即停止测试并保留现场状态、日志和截图。
7. 任何“提高速度、扩大安全区域、减小停障距离、取消禁行”的请求，都必须经过安全评审和变更审批，不能现场口头放行。

## 5. 连接、通信与机器人导入

> 下列步骤描述操作目的，不规定固定菜单名；当前版本可能把相关功能放在连接、设备、项目、机器人或资源管理页面中。**以当前界面字段和设备手册为准。**

### 5.1 连接前检查

1. 记录 AGV 编号、IP、控制器/导航模块地址、调度系统地址和当前任务状态。
2. 确认 AGV 未处于自动执行、充电对接、举升/伸叉、人工接管或其他会突然动作的状态。
3. 从工程电脑测试网络连通性；只能使用项目允许的诊断方式，不得扫描或修改非项目设备。
4. 登录具有必要权限的账号，确认当前连接对象、车型和项目名称，避免误连其他 AGV。
5. 读取并记录当前软件、地图、参数和运行状态；如读取失败，先处理通信问题，不要直接新建配置覆盖现场数据。

### 5.2 连接与通信核对

- [ ] 软件显示的 AGV 编号/型号与实体铭牌一致。
- [ ] 在线状态稳定，不是偶发上线后立即离线。
- [ ] 位姿、定位质量、电量、急停/安全状态和报警信息可以读取。
- [ ] 读取配置成功，且能识别当前地图/工程版本。
- [ ] 如需连接 RDS/MES/WMS，已明确单机控制与调度控制的当前主控权。
- [ ] 已确认是否允许“远程控制/任务下发/自动运行”；不需要时保持关闭。

### 5.3 机器人导入或模型确认

1. 若当前项目已有机器人资源，先确认车型、尺寸、轮距/轴距、载荷机构、传感器和导航方式，不要重复导入。
2. 若需导入机器人模型，使用当前版本支持的导入方式，并核对模型原点、车体外廓、旋转中心和传感器安装位置。
3. 对模型做静态检查：车体边界、前后方向、传感器盲区、载荷外廓、最大旋转包络是否与实物一致。
4. 先保存为新版本或新工程副本，完成空载低速验证后再作为项目基线。
5. 模型导入失败或字段含义不清时，保留原工程，不通过“猜参数”修复。

## 6. 配置层操作 SOP

### 6.1 地图新建、保存、备份、发布/下发

#### 6.1.1 新建或采集地图

1. 确认地图用途：单机定位/导航地图，还是调度系统布局/交通地图。
2. 确认导航方式与采集要求：二维码、激光、反光板、磁条、视觉或混合方式。
3. 清理采集区域内的临时物体，保持墙面、货架、固定设备和关键标志物处于实际工作位置。
4. 进入当前版本支持的建图/地图编辑功能，执行采集或导入。
5. 检查地图覆盖范围、边界、遮挡、重复特征、反光/玻璃干扰和定位质量。
6. 在地图上标注或记录原点、坐标轴方向、关键区域、禁行区、减速区、停障区和测试区。
7. 先保存为草稿版本，不立即发布到全部 AGV。

#### 6.1.2 保存和备份

每次修改至少保存以下内容：

- 原始地图/工程文件；
- 修改后的地图/工程文件；
- 站点、位置点、路径和参数导出物（当前版本支持时）；
- 机器人模型及载荷外廓；
- RDS/调度布局或交通规则相关配置（若有）；
- 任务模板、路线和接口映射（若有）；
- 版本号、修改人、时间、变更原因、适用 AGV 和回滚说明。

**建议备份命名：**

```text
项目_区域_对象_版本_日期_状态
例：WH01_A区_SMap_v20260805_01_PRECHECK
例：WH01_A区_SMap_v20260805_02_PUBLISHED
例：WH01_A区_RDSLayout_v20260805_01_BACKUP
```

备份完成后，随机打开或导入副本验证文件可读，不能只确认“文件已生成”。

#### 6.1.2.1 可执行备份步骤

1. 暂停会影响配置一致性的任务或发布操作，确认当前 AGV/调度系统处于可控状态。
2. 创建以项目、区域、对象、版本、日期和状态命名的备份目录，不覆盖上一次已验证备份。
3. 导出或复制地图、机器人模型、站点/位置点、路径、参数、安全区域、充电/停靠配置，以及 RDS/MES/WMS 相关配置（当前版本支持时）。
4. 在备份目录写入版本号、软件版本、AGV 型号、地图归属、操作者、时间、变更原因和回滚目标。
5. 关闭当前工程后重新打开备份，或在隔离副本中导入备份，检查文件可读、对象数量/名称和版本信息是否一致。
6. 记录验证结果并保留原始备份；验证失败时不得发布新配置，也不得删除原基线。

#### 6.1.3 发布/下发

1. 对比待发布版本与当前运行版本，确认差异清单。
2. 确认测试范围：单台 AGV、指定区域还是全车队；默认选择最小范围。
3. 将 AGV 置于安全状态，确认没有正在执行的关键任务。
4. 先执行当前版本支持的校验/检查，处理坐标、资源缺失、路径断开或参数越界提示。
5. 发布/下发前再次备份；记录操作者、时间和目标设备。
6. 下发后只做读取和静态核对，确认地图版本、点、路径、安全区和参数与目标版本一致。
7. 通过空载测试确认后，再允许进入带载或调度联调。
8. 发布失败、版本不一致或出现异常运动时，停止自动运行并按第 10 节回滚。

> **警告**：保存到工程、发布到本地项目、下发到 AGV、同步到 RDS 不是同一动作。现场必须逐一确认“当前操作写入了哪里”。

### 6.2 站点/位置点创建与编辑

#### 6.2.1 创建前确定

- 业务名称和唯一 ID；
- 点的类型：取货、放货、等待、转弯、充电、停靠、交接或其他；
- 地图坐标、朝向、到站判定方式和允许误差；
- 车体中心、货叉/顶升机构或载荷相对站点的定位关系；
- 站点前后的安全距离、是否需要等待/确认、是否受调度系统管控；
- 该站点属于单机地图、调度布局图还是两者都要配置。

#### 6.2.2 创建步骤

1. 在正确的地图/项目版本中选择创建站点或位置点的功能。
2. 在地图上选取实际停靠位置，设置位置坐标和车体朝向；坐标和角度的单位以当前界面为准。
3. 绑定业务类型、动作或停靠策略（仅在当前版本支持且已确认含义时）。
4. 设置到站判定、位置容差、角度容差、等待时间等字段时，先记录单位和默认值，再填写项目批准值。
5. 保存为新版本，检查点是否落在可行驶区域、路径连接处和实际停靠空间内。
6. 用低速、空载方式执行单点到站测试，验证“到站完成”不是仅仅“经过点”。

#### 6.2.3 编辑注意事项

- 移动位置点可能使相邻路径断开，必须重新做连通性检查。
- 修改朝向可能改变进站方向、旋转空间和载荷交接方向。
- 修改点 ID 会影响任务模板、MES/WMS 映射和调度规则；优先新增版本或建立兼容映射，不要直接改名覆盖。
- 位置点坐标应以当前地图坐标系为准，不能直接复制另一地图上的数值。
- 站点能到达不代表动作一定成功；到站后取放货、举升、扫码、门禁等动作必须单独验证。

### 6.3 路径创建、方向与连通性

#### 6.3.1 路径设计原则

1. 路径必须覆盖起点到终点的完整可行驶链路，不能只连接业务点而忽略中间转弯、窄道和等待点。
2. 检查车体外廓、载荷外廓、旋转包络、障碍物和安全区域，而不仅看线是否相交。
3. 对单向通道、交叉口、会车区、门区和坡道明确方向与优先级；由调度系统管理的交通规则要在 RDS/调度布局中同步核对。
4. 公开教程曾提到站点间可通过贝塞尔曲线等方式连接，并支持遇障停障、障碍消失后恢复；这只是公开资料中的通用说明，当前版本的曲线编辑、恢复策略和字段可能不同，**以当前界面字段和设备手册为准**。

#### 6.3.2 创建/编辑步骤

1. 选择正确地图和起点/终点位置点。
2. 创建或编辑连接线/曲线，设置必要的中间控制点，避免穿越墙体、设备、禁行区或安全边界。
3. 明确每条路径的行驶方向：双向、单向正向、单向反向或当前版本的其他方向表达。不要只根据线的绘制顺序猜测方向。
4. 核对当前版本提供的运动模式/导航模式字段；历史公开资料中的 `Movestyle` 仅作概念参考，不能直接照搬。
5. 检查路径与相邻点的连接状态、起终点方向、转弯半径、路径间隙和闭环/断点。
6. 对路径做静态校验；若软件提供路径预览、连通性检查或冲突检查，保存检查结果。
7. 以低速空载运行：起点离开、直线段、转弯、终点减速、到站停止和反向/返回路径均需验证。
8. 任何路径变更都要更新变更记录和回滚包。

#### 6.3.3 连通性验证方法

- **图检查**：每个任务所需的点都有入边/出边；不存在孤立点、断线或错误方向。
- **几何检查**：路径不穿越实体障碍、禁行区或不允许的安全区域；转弯和载荷外廓有余量。
- **实车检查**：从起点低速出发，逐段到达相邻点；记录定位质量、轨迹偏差、停靠误差和报警。
- **异常检查**：在批准的安全测试条件下验证障碍前停障、障碍消失后的恢复/重规划行为；若版本不支持自动恢复，不得假定会恢复。

### 6.4 速度、加减速和安全相关参数

#### 6.4.1 参数核对表

| 参数类别 | 需要确认的含义 | 单位/字段要求 | 验证方式 |
|---|---|---|---|
| 直线运动速度 | 直线段的目标/上限速度 | 以当前界面实际显示单位为准 | 空载直线运行，观察是否平稳、是否超出批准限值 |
| 旋转运动速度 | 原地或行进旋转的角速度/上限 | 以当前界面实际显示单位为准 | 空载低速旋转，观察摆动、定位和载荷稳定性 |
| 直线加速度/减速度 | 起步、制动变化率 | 以当前界面实际显示单位为准 | 观察起步冲击、停车距离和载荷滑移 |
| 旋转加速度/减速度 | 旋转起停变化率 | 以当前界面实际显示单位为准 | 观察旋转冲击和定位误差 |

| 减速区 | 进入特定区域前的速度限制或减速策略 | 区域、速度和触发条件以当前版本为准 | 进入区域前后记录速度和位置 |
| 停障距离/安全距离 | 障碍检测后开始减速或停车的距离逻辑 | 以当前界面、传感器和安全评估为准 | 由授权人员按安全测试方案验证 |
| 禁行/安全区域 | 不允许进入或需特殊限速的空间 | 区域边界以批准图纸为准 | 静态检查 + 低速边界验证 |

#### 6.4.2 设置流程

1. 先读取并备份当前参数，不在原基线上直接试改。
2. 将项目批准的速度限制、车型手册限制、区域安全要求和载荷要求逐项对照。
3. 优先设置区域/路径级安全限制，再核对全局默认值；若优先级不清楚，暂停并查当前版本说明。
4. 对直线和旋转分别设置/记录速度、加速度、减速度和必要的减速/停障参数；不把一个字段推断成另一个字段。
5. 检查空载、带载、低电量、不同地面条件下是否会采用不同限制。
6. 保存为新版本，先做静态校验，再做低速空载测试。
7. 逐步验证：直线 → 转弯 → 旋转 → 进站 → 停障 → 恢复；每一步通过后才进入下一步。
8. 带载验证必须使用真实或等效载荷，并遵守项目批准的最大载荷和重心条件。

### 6.5 充电站与停靠点（当前版本支持时）

1. 确认充电站/停靠点是单机导航对象、调度对象，还是两边都需要配置。
2. 核对进站方向、对接位置、充电触点/无线充电区域、允许停留范围和退出路径。
3. 确认电量阈值、回充触发、充电完成判定、占用释放和异常退出逻辑；字段含义以当前版本和充电设备手册为准。
4. 用空载低速测试：接近 → 减速 → 对接 → 充电状态确认 → 退出 → 恢复任务。
5. 验证充电站被占用时，调度系统是否会等待、改派或报警；不得假定调度策略。
6. 充电对接测试涉及电气和机械风险，必须由授权人员执行，禁止把普通停靠点直接当作充电点使用。

## 7. 运行层：任务/路线测试与联调

### 7.1 测试前确认

- [ ] 配置层版本已冻结，地图、点、路径、速度和安全区域均有记录。
- [ ] 测试 AGV 为指定设备，当前运行版本与待测版本一致。
- [ ] 调度系统处于测试/单车模式，其他 AGV、门禁、输送线和人员已隔离或制定协调方案。
- [ ] 任务模板中的点 ID 与配置层一致；没有遗留旧点、旧地图或旧任务。
- [ ] 已定义成功标准：到站、动作、状态回传、任务完成、异常恢复和日志可追溯。

### 7.2 空载单机测试

按以下顺序逐项通过：

1. 手动/点动确认起点定位正常，不执行完整任务。
2. 测试相邻点短路径：起步、直线、减速、到站。
3. 测试转弯和旋转：确认不碰撞、不越界、不异常抖动。
4. 测试完整路线：起点 → 中间点 → 终点 → 返回/退出。
5. 在批准条件下测试障碍物前停障，记录停车距离、状态和报警。
6. 移除障碍后观察恢复方式：自动恢复、重新规划、人工确认或保持停止，以实际版本行为为准。
7. 记录定位质量、实际轨迹、停靠误差、时间、报警码和处理结果。

### 7.3 带载验证

1. 使用现场实际载荷或已批准的等效载荷，记录质量、重心和外廓。
2. 从低风险短路径开始，再扩展到完整路线。
3. 重点观察起步/制动、转弯、旋转、窄道、坡道、停靠、取放货和载荷稳定性。
4. 验证带载时到站判定、动作互锁和任务完成条件。
5. 测试异常：载荷未到位、站点被占用、动作超时、通信短暂中断、障碍出现和任务取消；仅在批准的测试方案内操作。
6. 带载通过后，才进入生产节拍、车队调度和多设备联调。

### 7.4 与 RDS/MES/WMS 联调

- **主控权**：明确是 Roboshop Pro 单机控制、RDS 调度控制，还是 MES/WMS 通过接口触发任务。
- **对象映射**：站点 ID、任务 ID、路线 ID、设备 ID、状态码和报警码必须有映射表。
- **幂等性**：通信超时不能直接重复下发；先查询原任务真实状态，再决定等待、取消、重试或人工处置。
- **状态闭环**：验证已接单、执行中、到站、动作完成、任务完成、失败、取消等状态是否按约定回传。
- **交通规则**：RDS 可能承担多机交通规则和路径规划；不要只在单机地图中验证后就假设车队运行安全。
- **审计**：保留请求、响应、任务状态变化、操作者、配置版本和报警日志。

## 8. 常见报警与诊断方法

### 8.1 先分类，再处理

| 类别 | 典型现象 | 首要检查 | 处理原则 |
|---|---|---|---|
| 通信/在线 | 离线、心跳超时、读写失败 | 网络、IP、权限、控制器状态、主控权 | 不重复下发任务；先确认设备真实状态 |
| 定位/地图 | 定位丢失、位姿跳变、地图不匹配 | 地图版本、导航标志物、遮挡、坐标系、模型 | 停止自动运行，恢复已知好地图/定位条件 |
| 路径/规划 | 无可行路径、断点、方向错误、规划失败 | 点 ID、路径方向、连通性、禁行/安全区 | 先做静态图检查，再单段低速验证 |
| 障碍/安全 | 停障、保护区触发、急停 | 现场障碍、安全雷达、急停回路、区域配置 | 先清除危险，不得直接调大阈值绕过 |
| 运动/控制 | 过冲、抖动、异常加减速、越界 | 速度/加减速单位、车型模型、地面、载荷 | 立即降级到批准的安全测试参数并回滚异常版本 |
| 到站/动作 | 到站不完成、取放货失败、对接失败 | 位置/角度容差、动作互锁、机构/传感器 | 区分导航到站与业务动作失败 |
| 电量/充电 | 低电量、回充失败、充电未确认 | 电池、充电器、对接姿态、充电状态 | 按充电设备手册处置，不强行继续任务 |
| 调度/任务 | 任务卡住、重复任务、状态不一致 | 任务 ID、接口日志、队列、主控权 | 先查真实状态，再决定取消/重试/人工接管 |

### 8.2 现场诊断步骤

1. **先保证安全**：暂停任务或停止自动运行，确认 AGV、人员、载荷和周边设备处于安全状态；不得为复现报警而绕过急停或安全保护。
2. **固定现场状态**：记录时间、AGV 编号、位置、载荷、目标点、任务 ID、地图/参数版本、报警原文、报警码和当前运行模式。
3. **判断所属层级**：先区分通信/调度、配置/地图/路径、运动/机械、定位或安全触发，避免只根据报警文字直接修改参数。
4. **核对版本和主控权**：确认 AGV 当前实际加载的地图/参数与工程备份一致，并确认 Roboshop Pro、RDS、MES/WMS 中谁拥有当前控制权。
5. **执行静态检查**：对定位异常检查地图与导航基准，对路径异常检查点 ID/方向/连通性，对任务异常检查任务状态和接口日志；能静态确认的问题不要先实车反复试跑。
6. **按批准方案复现**：仅在隔离区域、低速、空载和授权人员在场的条件下复现；记录触发条件、停车/恢复行为和日志，不改变多个变量。
7. **决定处置**：按项目规则选择清障、人工确认、任务取消、单次重试、配置修复或回滚；通信超时先查询原任务真实状态，禁止盲目重复下发。
8. **关闭问题**：保存日志、截图和配置差异，填写诊断记录；只有在回归测试和负责人批准后，才恢复带载、车队或生产运行。

### 8.3 诊断记录模板

发生报警时至少记录：

- 时间、地点、AGV 编号和载荷状态；
- 软件/地图/任务/参数版本；
- 报警原文、报警码、首次发生时间和重复次数；
- 当时的运行阶段、目标点、路径和速度；
- 急停/安全雷达/定位/通信状态；
- 截图、日志、现场照片和复现步骤；
- 已采取的动作及结果；
- 是否回滚、回滚到哪个版本、谁批准；
- 后续责任人和关闭条件。

### 8.4 禁止的“快速修复”

- 不清楚字段单位时随意放大/缩小数值；
- 为绕过报警直接关闭安全区、停障或急停保护；
- 只改调度任务，不核对配置层地图/点/路径版本；
- 通过重复下发任务掩盖通信超时；
- 未备份就覆盖当前生产地图；
- 以单次成功运行代替多次、空载/带载和异常场景验证。

## 10. 上线前、上线后与回滚清单

### 10.1 上线前检查

- [ ] 软件、AGV 型号、导航方式、坐标系和单位已确认。
- [ ] 单机地图/SMap 与调度布局图已区分，版本一致性已核对。
- [ ] 地图、模型、点、路径、参数、安全区域、充电/停靠配置均已备份。
- [ ] 点 ID、路径方向、路径连通性和地图边界已检查。
- [ ] 空载短路径、完整路线、障碍停障和恢复行为已验证。
- [ ] 带载路线、到站、取放货/动作和停靠已验证（适用时）。
- [ ] RDS/MES/WMS 的主控权、映射、状态回传和异常处理已验证。
- [ ] 急停、安全雷达、禁行区、减速区和人员隔离措施已确认。
- [ ] 版本、参数记录、测试记录、变更单和回滚包可追溯。
- [ ] 已明确上线观察时间、值守人员和回滚触发条件。

### 10.2 上线后检查

- [ ] 首批任务使用指定测试路线和指定 AGV。
- [ ] 观察定位质量、轨迹、速度、停车、到站和任务状态。
- [ ] 检查报警是否增加，是否有重复任务、状态不一致或通信重试。
- [ ] 核对调度交通规则、交叉口/窄道和充电资源占用。
- [ ] 确认带载稳定性、动作成功率和实际节拍。
- [ ] 记录上线后问题及处理，不直接覆盖上线前基线。
- [ ] 观察窗口结束后，由负责人确认是否转为生产基线。

### 10.3 安全回滚步骤

触发条件包括：异常运动、定位不稳定、路径越界、停障/安全异常、任务状态失控、关键报警无法解释、带载风险或版本不一致。

1. **停止扩散**：暂停新任务和进一步发布，必要时停止自动运行。
2. **保证安全**：将 AGV 置于安全位置；按现场规程处理急停、人员和载荷，不在危险状态下导出/覆盖文件。
3. **保留证据**：保存报警、日志、当前版本、任务 ID、截图和现场状态。
4. **确认回滚目标**：选择最近一次已验证的地图/点/路径/参数/调度版本，不使用“可能可用”的旧文件。
5. **分层恢复**：先恢复配置层（地图、点、路径、参数、安全区域），再恢复运行层（任务模板、调度规则、接口映射）。
6. **小范围验证**：单机、空载、低速、短路径验证定位、连通性、停障和到站。
7. **恢复运行**：通过负责人批准后再进行带载和调度验证；逐步扩大范围。
8. **关闭变更**：填写回滚结果、影响范围、原因、后续修复计划和新的发布条件。

> 回滚不是简单“恢复旧地图”。如果任务模板、站点 ID、RDS 布局或接口映射也被改变，必须一起恢复到匹配版本。

## 11. 完整示例流程（示例值仅用于演示）

### 11.1 场景

单台 AGV 在 A 区执行“取货点 → 中转点 → 工位点”的路线，需配置地图、位置点、路径、速度，并完成空载、带载和上线前回滚准备。

> 以下对象名和数值都是**示例/起始值，不是通用安全值**；实际值以当前界面字段、车型手册和项目批准参数为准。

### 11.2 配置与测试步骤

1. **现场确认**
   - 记录 Roboshop Pro 版本、AGV 型号、导航方式、地图坐标系、速度单位、RDS/MES 主控权、急停和安全区域。
   - 任务范围限定为一台 AGV、A 区测试路线。

2. **连接与读取**
   - 连接指定 AGV，核对编号、在线状态、定位、电量和当前地图版本。
   - 导出当前配置包并验证备份可读取。

3. **建立地图版本**
   - 新建副本：`WH01_A区_SMap_NAV_v20260805_01_DRAFT`。
   - 确认地图覆盖起点、取货区、中转区、工位区和返回通道；确认没有误把 RDS 布局图当作单机地图。

4. **创建对象**
   - 位置点：`POS_PICK_01`、`POS_BUFFER_01`、`POS_WORK_01`。
   - 分别记录坐标、朝向、到站容差、动作/等待要求和适用载荷。
   - 创建路径：`PATH_PICK_TO_BUFFER_FWD`、`PATH_BUFFER_TO_WORK_FWD`，并核对返回路径方向是否需要单独配置。

5. **静态检查**
   - 确认每个点有正确入边/出边，路径没有断点、穿墙、穿越禁行区或超出安全边界。
   - 确认路径方向与 AGV 车头方向、取放货方向和调度规则一致。

6. **速度参数记录**
   - 记录直线速度、旋转速度、直线/旋转加减速、减速区和停障相关字段的当前原名与单位。
   - 仅设置项目批准的低风险起始参数；本文中的直线速度 `0.30`、旋转速度 `10` 只是记录格式示例，禁止直接录入，必须写明当前界面单位、批准依据，并标记“示例/起始值，不是现场放行标准”。

7. **空载短路径测试**
   - 先执行 `POS_PICK_01 → POS_BUFFER_01`。
   - 检查起步、直线、转弯、减速、到站和停车稳定性。
   - 再执行 `POS_BUFFER_01 → POS_WORK_01`，确认定位和路径连通性。

8. **空载完整路线与障碍测试**
   - 执行完整路线并记录轨迹、时间、到站误差和报警。
   - 在批准的安全方案下放置测试障碍，验证停障；障碍移除后，按当前版本实际行为验证自动恢复、重规划或人工确认。

9. **带载验证**
   - 使用已批准的等效载荷，记录载荷质量、重心和外廓。
   - 重复短路径和完整路线，重点观察起停、转弯、到站、动作互锁和载荷稳定性。

10. **运行层联调**
    - 从 RDS/MES/WMS 发送唯一任务 ID，确认接单、执行中、到站、动作完成和任务完成状态。
    - 模拟通信超时或站点占用时，先查询原任务状态，不直接重复下发。

11. **发布**
    - 形成发布包：地图、点、路径、参数、任务模板和调度映射。
    - 先发布/下发到指定 AGV，核对版本一致，再由负责人批准进入上线观察。

12. **回滚演练/准备**
    - 保留上线前备份 `WH01_A区_CONFIG_v20260805_01_BACKUP`。
    - 记录触发条件：定位跳变、路径异常、停障不符合要求、带载不稳、状态闭环失败等。
    - 若触发，暂停任务、保留日志、恢复已验证版本，按第 10.3 节完成单机空载验证后再决定是否恢复生产。
