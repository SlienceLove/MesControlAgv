# 两设备当前运行任务展示

用户确认紧凑单行方案：在开盖分液和离子色谱设备页列表上方显示当前任务；不以最近创建、当前选中或历史 Running 记录代替设备实时状态。

## 实施方案

- 起初在已授权主目录 UI 分支实现。审查发现现有 LastSeenAtUtc 会被心跳刷新，不能证明设备状态仍新鲜；因此从共同基线 develop `4855e14` 建立 `feature/device-current-task-display`，原样保留本轮未提交成果和现场资料。前后端联动在同一任务分支完成，UI 分支基线未被覆写。
- 仅给现有 GET 状态响应增加可空 `LastDeviceStatusAtUtc`，来自 MES 已记录的有效 Device/UpdateInfo 接收时间。心跳、无 status 的更新不推进它，重新认证/新连接清空它。旧 MES 无该字段时当前任务显示“无法确认”，不以通讯时间代替；须后续批准更新 MES 才能现场验收此项。不改变厂家协议、命令、数据库或后端任务状态。
- 开盖分液：在线且最新状态为 Running、任务列表读取成功且唯一任务行为 Running，才展示其名称及编号；多条/缺失运行行显示“运行中，任务待确认”。
- 离子色谱：目标设备 STN61_01 在线、状态及活动标志一致且没有结束标记后，以当前上报 sampleId / taskUuid 精确匹配中控记录，展示样品名称和业务编号。多样品或重复匹配不取第一条。只有实时名称时显示名称和“编号待确认”；无身份时明确待确认，不暴露协议 UUID 或通讯样品号。
- 在线空闲显示无运行任务；离线、查询失败、超过 60 秒未读到有效状态时撤下任务身份。离子色谱同时检查设备状态更新时间，而非仅检查心跳/通讯时间。旧任务表可以保留，当前任务栏不复用其运行标记。在线徽标与当前任务共用本轮状态读取来源，避免一个已刷新另一个仍旧。
- 页面可见时每 5 秒只读刷新设备状态，复用视图模型的并发门控；不定时加载历史详情、切换用户选中行或发送设备命令。页面卸载停止计时，显示检查会使过期数据失效。
- 保留已有紧凑布局、任务列表、模板/批量入口和控制准入；窄窗摘要省略，完整内容悬停查看。

精确身份关联、跨设备/重复/冲突/多样品拒绝猜测，在线空闲/离线/部分失败/过期/恢复，页签切换和数据刷新通知，820×480 带异常提示及联调区的实际布局。随后 WPF 全量测试、只读审查、UI → develop 集成验证。现场 WPF/MES 不在此次实现中再次重启。
