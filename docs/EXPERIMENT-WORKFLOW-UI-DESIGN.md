# 实验流程界面规划

> 状态：长期界面与交互规划；UI 阶段 1 / G2 编辑器收敛已实现并等待验收，其余阶段仍为规划
> 基线日期：2026-08-20
> 关联架构：[EXPERIMENT-WORKFLOW-ARCHITECTURE.md](EXPERIMENT-WORKFLOW-ARCHITECTURE.md)
> 画布技术评估：[EXPERIMENT-WORKFLOW-CANVAS-EVALUATION.md](EXPERIMENT-WORKFLOW-CANVAS-EVALUATION.md)

## 1. 目标

实验流程模块面向长期、重复的实验编排和运行监控，不是展示型页面。界面应帮助用户快速完成以下工作：

1. 找到适用的实验方案并确认配置完整。
2. 通过可视化流程图配置 AGV、机械臂、仪器、等待、判断和人工步骤。
3. 在发布前发现设备能力、站点、参数、物料和异常路径问题。
4. 将已发布方案放入排程，查看资源冲突和阻塞原因。
5. 在运行时同时看到流程位置、设备操作、实时读数、日志和人工待办。
6. 对异常、未知结果和人工操作形成完整审计。

## 2. 用户角色

| 角色 | 主要任务 | 默认权限 |
| --- | --- | --- |
| 流程设计人员 | 建立方案、编辑流程、校验和提交发布 | 编辑草稿，不直接控制设备 |
| 实验操作员 | 启动已批准任务、运行监控、人工确认和异常处理 | 运行操作，不能修改已发布版本 |
| 设备维护人员 | 查看原始状态、执行批准的初始化或调试 | 独立维护入口和受控权限 |
| 审核/管理人员 | 发布审批、日志审计、权限与策略管理 | 审核和只读追溯 |

流程设计权限和设备控制权限必须分离。能够在画布上放置某类节点，不等于能够在现场执行该设备写操作。

## 3. 设计原则

### 3.1 面向操作工作流

- 页面保持安静、紧凑和可扫描。
- 主要信息通过表格、树、画布、时间线和属性面板呈现。
- 不使用大面积宣传文案、装饰性渐变或多层嵌套卡片。
- 页面区域采用固定工具栏和分栏布局，动态内容不能导致整体跳动。
- 常用操作使用图标或图标加文字，危险操作需要明确文字和二次确认。

### 3.2 状态必须同时用文字和视觉表达

不能只依赖颜色。建议状态语义：

| 状态 | 颜色倾向 | 图标/文字 |
| --- | --- | --- |
| 未开始 | 中性灰 | Pending |
| 准备/可执行 | 蓝 | Ready |
| 正在运行 | 深蓝 | Running + 活动指示 |
| 等待条件/资源 | 琥珀 | Waiting + 原因 |
| 成功 | 绿 | Succeeded |
| 失败/超时 | 红 | Failed / Timed out |
| 结果未知 | 紫红或高对比警示色 | Unknown，必须人工处理 |
| 已取消/跳过 | 灰 | Cancelled / Skipped |

`Unknown` 不能与普通失败显示成同一种状态，因为它禁止盲目重试。

### 3.3 配置应使用领域控件

- 站点使用可搜索站点选择器，不使用普通文本框。
- 设备使用设备选择器，显示在线状态和能力匹配。
- 枚举使用下拉菜单或分段控件。
- 布尔设置使用开关或复选框。
- 超时、采样间隔和次数使用带单位的数值输入。
- 条件使用结构化条件构建器，不允许输入任意代码。
- 颜色使用色板，仅用于确实需要用户选择颜色的场景。
- 原始参数键值表只保留在受限的诊断视图，不作为正常流程配置入口。

## 4. 一级信息架构

实验相关模块建议拆成以下导航入口：

```text
实验方案
流程设计
任务排程
运行监控
设备中心
日志审计
系统管理
```

各入口职责：

| 页面 | 职责 | 不负责 |
| --- | --- | --- |
| 实验方案 | 方案、物料、默认参数、布局和流程版本引用 | 直接编辑运行中流程 |
| 流程设计 | 节点、边、配置、校验、版本和发布 | 决定任务执行时间 |
| 任务排程 | 任务池、计划时间、优先级和预计资源 | 推进流程节点 |
| 运行监控 | 当前实例、节点状态、设备操作、人工待办 | 修改已发布定义 |
| 设备中心 | 设备健康、能力、负载和维护状态 | 替代流程编排 |
| 日志审计 | 跨流程、设备和用户的追溯 | 执行未经授权的控制操作 |
| 系统管理 | 用户、角色、权限、能力策略 | 日常实验操作 |

现有 WPF 可以继续使用顶层 Tab，但随着模块增加，应改成稳定的左侧导航或顶层模块导航，避免一行 Tab 过长。

## 5. 实验方案页

### 5.1 页面布局

```text
+--------------------------------------------------------------------------------+
| 实验方案                                      [导入] [新建方案]                 |
+--------------------------------------------------------------------------------+
| 筛选: 状态 | 类型 | 设备能力 | 修改人       搜索...                            |
+--------------------------------------------------------------------------------+
| 名称          当前版本  状态      完整度  所需能力       修改时间      操作      |
| 阴离子检测    v4        已发布    完整    AGV/机械臂/IC  08-19 13:20   查看      |
| 空载验证      v2        草稿      3项缺失  AGV/IC         08-19 11:05   继续编辑  |
+--------------------------------------------------------------------------------+
| 选中方案详情: 基础信息 | 物料 | 布局 | 流程版本 | 变更记录                     |
+--------------------------------------------------------------------------------+
```

### 5.2 完整度检查

完整度不是一个模糊百分比，应列出可操作问题：

```text
- 缺少样品托盘规格
- IC_01 在当前 Profile 中只读，流程包含控制能力
- 机械臂程序 ARM_LOAD_IC 未在能力目录中启用
- 流程节点 8 没有超时路径
```

点击问题应直接跳转到对应方案字段或流程节点。

### 5.3 版本操作

- 草稿：编辑、校验、删除。
- 已校验：发布、退回草稿修改。
- 已发布：查看、复制为新版本、停用。
- 已归档：只读查看和比较。

发布版本不能直接保存覆盖。用户点击编辑时创建新草稿版本。

## 6. 流程设计器

### 6.1 总体布局

G2 已通过 [画布技术评估](EXPERIMENT-WORKFLOW-CANVAS-EVALUATION.md) 中的 Spike 门禁，并在主窗口中以
`IWorkflowCanvasSurface` 隔离 `NodifyCanvasAdapter`。Nodify 只是可替换的画布内核，不是流程领域模型或流程引擎：

```text
+--------------------------------------------------------------------------------+
| 返回  流程名称 / v5 草稿   [撤销] [重做] [自动布局] [校验] [保存草稿] [发布]   |
+------------------+------------------------------------------+------------------+
| 节点与能力       |                                          | 属性             |
| 搜索...          |                 流程画布                 |                  |
|                  |                                          | 基础             |
| 控制             |  [开始] -> [AGV 到 IC_01] -> [机械臂上样] | 设备与能力       |
| 设备             |                           |              | 输入输出         |
| 等待             |                           v              | 超时与异常       |
| 数据与人工       |                    [等待压力稳定]         | 资源             |
|                  |                         /       \         |                  |
| 不可用能力(2)    |                    [继续]       [超时]     |                  |
+------------------+------------------------------------------+------------------+
| 校验 3 | 警告 1 | 能力检查 1 | 版本差异 | 点击问题定位节点                  |
+--------------------------------------------------------------------------------+
```

桌面最小目标分辨率建议为 `1440 x 900`。左侧面板可在 `180-240 px` 调整，右侧属性面板可在 `320-420 px` 调整；画布保留最小宽度，面板折叠不能让节点或文字互相遮挡。

### 6.2 顶部命令栏

按使用频率分组：

```text
导航 | 编辑历史 | 布局与缩放 | 校验 | 生命周期操作
```

建议命令：

- 返回方案。
- 撤销、重做。
- 自动布局、适应画布、缩放。
- 校验和能力检查。
- 保存草稿。
- 发布。
- 更多菜单：导入旧格式、导出定义、版本比较、复制版本。

撤销、重做、缩放等应使用熟悉图标并提供工具提示，不使用 Unicode 表情作为按钮图标。

### 6.3 左侧节点与能力面板

节点分类：

```text
控制
  开始、结束、条件、并行、汇合、子流程

运输
  AGV 移动到站点、等待到站

机械臂
  执行程序、抓取、放置、回原点、读取状态

仪器
  读取状态、等待稳定、控制操作

等待与人工
  定时等待、设备条件、外部信号、人工确认

数据
  读取运行参数、映射结果、写入实验结果
```

能力项应显示：

- 名称和设备类型。
- 当前 Profile 是否可用。
- 只读、受控写入或维护级别。
- 不可用原因。

不可用能力可以在单独分组中显示为禁用，帮助设计人员理解缺口，但不能拖入可发布流程。离子色谱写操作应显示为不可用并给出安全门禁原因。

### 6.4 画布交互

必须支持：

- 从能力面板拖入节点。
- 拖动节点和框选多选。
- 端口拖拽连线。
- 复制、粘贴和删除。
- 对齐、等距分布和自动布局。
- 缩放、平移、适应全部。
- 小地图在大型流程中按需开启。
- 点击校验问题定位并高亮节点或边。

避免把常用动作放在右键菜单中作为唯一入口。删除和危险动作需要键盘操作与明确命令入口共同支持。

### 6.5 节点视觉结构

节点尺寸应稳定，建议基础宽度 `180-220 px`，内容过长时换行或在属性面板查看，不因状态文字临时扩大节点。

```text
+--------------------------------+
| [图标] AGV 移动          Ready  |
| 到离子色谱站 IC_01              |
| AGV: 自动选择 / 超时: 5 min     |
| in                         out  |
+--------------------------------+
```

节点上只显示扫描所需信息：

- 类型图标和名称。
- 业务标题。
- 关键设备/站点或条件摘要。
- 校验或运行状态。
- 输入输出端口。

完整参数、审计和原始读数放到属性/详情面板，避免节点变成小型表单。

### 6.6 边与端口

连接线颜色表达语义，而不是简单按第几条分支循环分配。边必须有文字标签：

| 边 | 标签示例 |
| --- | --- |
| 成功 | 成功 |
| 失败 | 失败 |
| 超时 | 超时 |
| 条件 | 压力 <= 12 MPa |
| 取消 | 已取消 |
| 补偿 | 进入恢复 |

同一节点的输出端口应有明确名称，例如 `success`、`failure`、`timeout`。条件网关的边标签由条件构建器生成，不能只显示自由文本。

### 6.7 右侧属性面板

属性面板按折叠区组织，但不把每个区域做成独立浮动卡片：

```text
基础信息
设备与能力
配置参数
输入与输出
资源要求
超时与重试
异常路径
高级信息
```

#### AGV 移动节点

```text
能力              agv.navigate-to-station
目标站点          [IC_01          v]
AGV 选择           [自动选择       v]
到站判定          [设备任务 arrived]
导航超时          [5] min
资源              IC_01 站点
失败端口          failure
超时端口          timeout
```

站点选择器应同时显示 Profile 启用状态和地图一致性，不允许输入不存在的站点代码。

#### 机械臂节点

```text
设备              [ARM_01          v]
能力              robot.execute-program
程序模板          [LOAD_IC_SAMPLE  v]
等待完成确认      [开启]
确认超时          [90] s
前置条件          AGV 已到站、工位空闲
失败处理          [进入人工恢复    v]
```

程序模板必须来自设备能力目录，不能在流程中输入任意机械臂脚本。

#### 仪器读取/等待节点

```text
仪器              [D160_01         v]
能力              instrument.wait-until-stable
监控字段          [pressureMpa     v]
比较              [小于或等于      v]
阈值              [12.0] MPa
采样间隔          [2] s
持续满足          [30] s
最大等待          [10] min
数据过期阈值      [5] s
```

当前 D160 读取节点可以配置已验证字段；写入能力保持禁用。界面中不得出现寄存器地址输入框。

#### 条件节点

```text
数据来源          [等待压力稳定.outputs.pressureMpa]
操作符            [<=]
比较值            [12.0]
数据缺失          [进入 failure]
默认分支          [否]
```

### 6.8 校验与问题面板

底部面板使用 Tab：

```text
结构校验 | 参数校验 | 能力检查 | 物料/布局 | 版本差异
```

问题列表列：

```text
级别 | 代码 | 节点/边 | 问题 | 建议处理
```

支持：

- 点击定位。
- 按级别和节点筛选。
- 显示当前校验器版本和时间。
- 发布前自动重新校验，不能仅依赖旧结果。

永久显示大量操作说明会挤占空间。常规帮助放在工具提示、首次空状态和帮助入口中。

### 6.9 生命周期状态

标题栏清楚显示：

```text
本地草稿 / MES 草稿 / 已校验 / 已发布 / 已归档
```

不同状态下的操作：

| 状态 | 可编辑 | 可校验 | 可发布 | 可运行 |
| --- | --- | --- | --- | --- |
| 本地草稿 | 是 | 本地检查 | 否 | 否 |
| MES 草稿 | 是 | 是 | 校验后 | 否 |
| 已校验 | 受控修改 | 是 | 是 | 否 |
| 已发布 | 否 | 只读复核 | 否 | 是 |
| 已归档 | 否 | 否 | 否 | 否 |

发布后点击编辑应创建下一版本草稿，并在界面中显示来源版本。

## 7. 运行监控页

### 7.1 总体布局

```text
+--------------------------------------------------------------------------------+
| RUN-20260819-0042  阴离子检测 / v5   Running    [暂停] [取消] [更多]          |
| 样品 B-1042 | 开始 13:40 | 已运行 00:18:12 | 当前: 等待压力稳定               |
+-----------------------------------------------+--------------------------------+
|                                               | 当前节点                       |
|              只读流程画布                     | 状态: WaitingForSignal         |
|                                               | D160_01 在线                   |
| 已完成: 绿色                                  | 压力: 9.80 MPa                 |
| 当前: 蓝色高亮                                | 连续满足: 18 / 30 s            |
| 等待: 琥珀                                    | 最大等待剩余: 06:22            |
| 失败/未知: 明确标识                           | [查看设备证据]                 |
+-----------------------------------------------+--------------------------------+
| 时间线 | 设备操作 | 实时数据 | 人工待办 | 审计                                |
+--------------------------------------------------------------------------------+
```

运行画布为只读，不允许拖动节点造成用户误以为修改了流程定义。可以允许平移、缩放和选中节点查看详情。

### 7.2 当前节点详情

详情至少包括：

- 节点类型和配置摘要。
- 本次输入快照。
- 状态、尝试次数和开始时间。
- 设备操作 ID 和关联 ID。
- 最新设备状态及数据时间。
- 超时和重试/对账策略。
- 可执行的人工动作及权限要求。

对 `Unknown` 状态显示独立处理面板：

```text
结果未知，禁止自动重试
原因：写入响应超时
建议：读取设备状态并人工对账
[刷新状态] [记录现场结果] [终止流程]
```

不能提供一个没有上下文的“重试”按钮。

### 7.3 时间线

时间线统一显示：

- 流程准入和版本。
- 节点开始、等待、完成和异常。
- 设备命令接受、状态变化和对账。
- 人工确认和操作者。
- 暂停、恢复、取消。
- 外部系统信号。

每条事件可展开查看白名单字段，不默认显示完整设备载荷。

### 7.4 实时数据

核心实验允许定制字段，例如 D160 压力、流量、温度和电导率；普通流程使用标准化状态视图。数据必须显示：

```text
数值 + 单位 + 采集时间 + 数据质量/映射可信度
```

不同设备不要被强制塞进同一固定指标卡布局。使用可配置的紧凑字段表或趋势图区域。

## 8. 任务排程页

排程与流程设计器分开。

### 8.1 页面布局

```text
+--------------------------------------------------------------------------------+
| 任务排程          日期 [2026-08-19]  [重新计算] [发布排程]                     |
+--------------------------+-----------------------------------------------------+
| 待排任务池               | 时间轴 / 资源泳道                                  |
|                          | 13:00     14:00     15:00                            |
| B-1042  高  Ready        | AGV_01     [运输----]                               |
| B-1043  中  Blocked      | ARM_01        [上样]     [卸样]                     |
| B-1044  中  Ready        | D160_01          [检测----------------]             |
|                          | IC_01       [占用----------------------]             |
+--------------------------+-----------------------------------------------------+
| 选中任务: 方案、版本、样品、优先级、预计时长、资源、阻塞原因                 |
+--------------------------------------------------------------------------------+
```

### 8.2 排程操作

- 从任务池拖入时间轴。
- 修改优先级和计划时间。
- 显示设备维护窗口和不可用时段。
- 检测同一资源冲突。
- 显示流程版本预计资源需求。
- 解释阻塞原因，而不是只显示“不可排程”。

首期不需要复杂自动优化算法。先支持人工排程、确定性冲突检查和清楚的阻塞原因。

## 9. 设备中心与模块调试

### 9.1 设备中心

设备列表建议字段：

```text
设备 | 类型 | 在线 | 业务状态 | 控制策略 | 当前任务 | 负载 | 最后更新
```

设备详情 Tab：

```text
概览 | 能力 | 当前数据 | 运行历史 | 告警 | 维护
```

能力页明确区分：

- 已启用只读。
- 已启用控制。
- 已实现但策略禁用。
- 当前 Profile 不支持。
- 尚未验证。

### 9.2 模块调试

调试入口不放在流程设计器属性面板中。维护人员从设备中心进入，页面必须显示：

- 当前运行模式。
- 控制策略和安全门禁。
- 设备是否被流程占用。
- 操作前置检查。
- 操作影响和停止条件。
- 每次动作的审计记录。

离子色谱仪当前只提供只读状态页，不提供启泵、改温度、进样或启动检测按钮。

## 10. 日志审计页

### 10.1 检索维度

- 时间范围。
- 实验方案、任务和流程运行 ID。
- 样品/批次。
- 节点执行 ID。
- 设备和设备操作 ID。
- 用户。
- 事件类型和结果。
- 关联 ID。

### 10.2 展示形式

默认使用可排序表格，选择记录后在侧面显示详情。支持切换成一次流程运行的时间线，不把所有日志强制做成卡片。

不可篡改在本项目中应解释为：业务 API 不提供更新/删除审计记录的能力，并通过数据库权限、备份和后续完整性校验提高可信度。不能仅靠界面隐藏删除按钮宣称不可篡改。

## 12. 关键操作流程

### 12.1 新建并发布流程

```text
新建方案
  -> 填写基础信息和物料
  -> 创建流程草稿
  -> 拖入节点并配置
  -> 结构/能力/物料校验
  -> 保存 MES 草稿
  -> 发布审核
  -> 生成不可变版本
```

### 12.2 从任务到运行

```text
基于已发布方案创建实验任务
  -> 完整性检查
  -> 放入任务池
  -> 人工或自动排程
  -> 运行准入
  -> 获取首批资源租约
  -> 启动 WorkflowRun
  -> 运行监控和审计
```

### 12.3 异常处理

```text
节点失败/超时/未知
  -> 在运行画布高亮
  -> 展示设备状态和操作证据
  -> 根据显式异常边自动进入安全处理
     或创建人工待办
  -> 记录处理人、理由和结果
```

## 14. 分阶段界面落地

### UI 阶段 1：画布 Spike 与编辑器收敛（G2 已实现，待验收）

- 已完成 Nodify Spike，并通过画布适配层接入主编辑器。
- 已接入现有 Draft/Validate/Publish/DryRun，统一规范图文档、节点和显式边。
- 已移除旧编辑器入口，WPF 可观察集合仅保留为展示投影。
- 已提供旧格式显式兼容导入和用户可见转换报告，写出格式统一为 Graph Document v2。
- 设备执行边界未改变，仍不新增现场设备写入。

验收重点：保存、加载、发布往返无数据丢失，两套编辑器不再同时承担业务编辑。

### UI 阶段 2：类型化属性和校验

- 按节点 schema 生成属性控件。
- 站点、设备和能力选择器。
- 校验问题定位。
- 发布状态和版本比较。
- 不可用设备能力展示。

验收重点：错误配置无法发布，用户不再直接编辑通用参数键值表。

### UI 阶段 3：运行监控

- 只读运行画布。
- 当前节点详情。
- 节点执行和设备操作时间线。
- 人工待办、暂停、取消和 Unknown 处理入口。

验收重点：重启恢复后界面能显示一致状态，危险操作有权限、原因和审计。

### UI 阶段 4：方案和排程

- 实验方案完整度。
- 任务池和人工排程。
- 资源时间轴和阻塞原因。
- 设备负载视图。

验收重点：排程和流程设计职责清晰，不在流程画布中配置计划时间。

### UI 阶段 5：设备中心、审计和权限

- 标准设备状态页。
- 独立维护调试入口。
- 跨实体日志检索。
- 角色和动作权限。

## 15. 视觉和可用性验收清单

- 在 `1440 x 900` 和 `1920 x 1080` 下主要按钮、标题和面板不重叠。
- 节点、端口、状态标签使用稳定尺寸，状态变化不引发布局跳动。
- 最长站点名、设备名和节点名能够换行或省略，并可查看完整内容。
- 画布缩放后节点端口仍可操作，连接标签不被节点遮挡。
- 所有状态不仅使用颜色，还包含图标或文字。
- 键盘焦点清晰，常用编辑操作支持快捷键。
- 图标有工具提示，不使用难以理解的自绘符号。
- 危险操作与普通命令在位置、颜色和确认流程上明确区分。
- 空状态提供下一步动作，不长期占用大面积说明文字。
- 实时刷新不阻塞 UI，也不把仪器串口读取附加到高频 AGV 刷新循环。
- 发布、运行和设备维护操作均显示当前环境/Profile/运行模式。

## 16. 本阶段界面决策与状态

G2 实施结果和后续约束如下：

1. Nodify 已通过独立 Spike 门禁并接入主编辑器。
2. 画布已通过 `IWorkflowCanvasSurface` 适配层隔离，未来仍可替换 Diagram 控件。
3. 主窗口手工 Canvas 和历史 `实验流程设计` 编辑器均已退出。
4. 右侧属性面板由节点类型 schema 驱动，属于 G3 工作。
5. 图文档已支持成功、失败、超时和条件等独立边语义；G3 继续补齐类型化校验。
6. 流程设计、任务排程和运行监控是三个独立页面。
7. 模块调试与正常流程运行使用不同入口和权限。
8. D160 当前仅在设计器中提供只读节点能力，控制能力保持禁用。

UI 阶段 1 随 G2-C 完成实现，G2 总体验收已于 2026-08-20 通过。G3 类型化节点、能力目录和发布校验是下一阶段，但尚未开始；不得借机新增设备执行路径或实体设备运行按钮。具体交付顺序和验收标准见 [EXPERIMENT-WORKFLOW-IMPLEMENTATION-PLAN.md](EXPERIMENT-WORKFLOW-IMPLEMENTATION-PLAN.md)。
