# 工作站异常导入人工核对结案

## 已批准目标

保留原始Unknown/Importing批次日志，另存人工确认“已创建、回读异常”的审计记录，仅解除对应条目对后续新批次的阻断。不标为自动回读通过，不重发旧任务，不初始化/启动/删除厂家任务。用户已批准此方案；现场实施与服务切换需另行安排。

## 实现边界

- 最新develop 2d73132起点，feature/workstation-import-reconciliation / .worktrees/workstation-import-reconciliation，前后端同分支。
- GET列出待核对及已人工结案的异常条目；POST结案必须提供请求号、精确任务号、原PayloadHash、原日志SHA256、确认操作号、操作人、原因及两项显式确认（任务已创建、明细已核对）。
- 服务使用与导入相同的进程锁及跨进程文件锁。首次结案重新只读查询设备空闲状态和精确任务详情，要求编号、名称一致且任务Waiting；故障/离线/运行中/不存在/身份不符均拒绝。明细核对是人工声明，不能称作机器验证。
- 查询详情后再次检查在线空闲，记录最后状态快照。设备状态采集时间须在确认时间前60秒至后10秒内；审计读取时校验这一历史时间关系并拒绝未来确认时间，但合法历史结案不会因经过数日而失效。
- 原日志字节不改；审计侧文件通过新文件原子落盘。绑定原日志哈希和PayloadHash，记录原状态/原因、设备快照与确认内容。损坏、错配或过期审计失败关闭，不能解除阻断。
- 相同操作号和内容返回既有记录，不再查询或写入设备；同操作号用于另一任务/批次或不同内容拒绝。只解除被结案的条目，其他Unknown仍阻断。原请求重放不重新导入，附带人工结案信息但原始状态保持。
- WPF任务窗口新增“异常批次核对”页，手动加载，选条目、填原因、两项勾选、二次确认后提交。首次打开不联网、不结案。超时后保留确认编号并要求刷新核对，不自动重试；重新打开仍可查到服务端审计。

## 验证计划

服务：成功结案原日志不变/零设备写入、仍可查审计、跨设备/编号/哈希拒绝、所有输入确认、设备状态/身份拒绝、同号幂等和冲突、并发锁、损坏/过期侧文件不解锁、其他Unknown保留、新批次可继续但旧批次从不重发。

界面/HTTP：读取路径与身份检查、缺接口提示、未勾选/空原因/取消确认零POST、忙时不可重复/关闭、确认成功显示人工结案而非自动导入成功、响应身份异常/超时要求核对、小窗口布局。

## API与存储

- GET `/api/workstations/{deviceId}/task-batches/reviews`：仅扫描本地批次日志与审计，不访问设备，保留待核对及已人工确认记录。
- POST `/api/workstations/{deviceId}/task-batches/{requestId}/reconcile-created`：只访问设备状态/详情GET，再保存本地审计；无厂家写请求。
- 审计目录为原JournalDirectory下的`reconciliations/`，文件名为请求GUID加任务编号SHA256，防止任务编号作为路径。必须与原批次目录一起保留/备份，不能只迁移主JSON。
- 原批次重放保持Unknown（或将历史Importing呈现Unknown），`Reconciliations`附带人工确认记录，不重发。仅对应审计完整、身份/指纹/时间关系均正确的条目不再阻断新批次；新批次仍做能力、空闲、查重、单位与严格回读验证。
- 操作人是本地接口的显式审计字段，不代替将来的账号权限体系；本轮不接管未集成的用户权限分支。
