# 工作站启动前双瓶条码校验

## 已确认目标

现场单条任务曾以null请求启动，厂家回复“启动成功”却弹出空条码确认。用户已确认补充校验：WPF、MES及设备网关统一要求1号和2号样品瓶条码非空；缺少时明确指出瓶号且零设备启动请求。两条测试编号可手动填写，不自动补造。任务导入不要求条码、不自动启动。

## 范围与设计

1. 复用SampleWorkstationTaskBarcodes，集中校验两字段，null、缺字段、空串和纯空白均拒绝；合法内容Trim后显式随启动请求传递。保留现有条码字符及编码兼容，不新增长度、唯一性或必须不同的限制。
2. WPF已有联调启动入口增加两项条码输入和明确缺失提示；校验在确认弹窗及HTTP调用之前。确认弹窗展示任务及两条条码。仅启用现有联调入口时可见，不修改现场默认开关、不新增自动启动入口。切换所选任务清空输入，避免误带上一任务条码。
3. WPF客户端、MES启动HTTP入口/转发客户端、Adapter启动入口/驱动均拒绝无条码启动。保留必要旧方法签名以兼容编译，但调用时明确返回“缺少1号、2号样品瓶条码”，且不进入下游发送。HTTP返回400及明确未发送/结果已知，不把参数校验失败记成设备执行结果未知。
4. 已准备的工作流继续使用已核验的两瓶绑定条码。未准备且没有两条条码的执行路径必须在发送之前明确拒绝；不从环境、旧任务或配置猜测条码，不自动补绑、不改变历史执行记录。
5. 保留“启动请求已接收”与“已运行”的区分、二次确认、一次发送及不自动重试行为。不修改厂家协议，不清理历史Running、不改当前任务名称关联；独立legacy模板执行模块不在本轮范围。

## 离线验收

- 每一边界覆盖null请求/缺字段、两空、只缺1号、只缺2号、空白、合法测试编号及特殊字符编码。
- 验证非法输入零HTTP/零驱动调用/零厂家请求；UI不弹启动确认，直接提示缺少瓶号。
- 合法值Trim并保留内容，启动报文同时包含两条；取消确认零请求，忙时无重复提交。
- 回归导入、条码更新及准备工作流，确保导入仍可先于条码绑定执行。
- 测试使用本地替身，不向现场设备发送任何请求。WPF排除2项会跨worktree写历史文件的旧ShineLabHandoffRehearsalTests。
