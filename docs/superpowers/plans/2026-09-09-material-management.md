# 物料管理模块实施计划

> 对应设计：`docs/superpowers/specs/2026-09-09-material-management-design.md`
>
> 本计划是在 `writing-plans` 技能不可用时按同等粒度手工整理的。范围严格限制在第一阶段：样品/耗材登记、默认仓库库存、扫码溯源、任务预占/释放/消耗记录和 WPF 页面。不得接入进样器真实启动或其他厂家写接口。

## 全局约束

- MES 是唯一数据源；WPF 不直接访问数据库，所有业务读写经过 `IMesClient` 和 MES HTTP API。
- 保留 `ExperimentPlan.MaterialRequirements`、`ExperimentJob.SampleId` 和 `SampleBatchId` 的兼容语义；不把方案快照改造成库存台账，不强制回填历史任务。
- 样品按单件/单容器追踪，耗材按批次+库位计量；余额只通过事务流水变化。
- 预占不扣 `onHand`；取消/失败释放预占；实际使用记录才扣减并追加消耗流水。
- 所有写命令带请求号/关联号并幂等；过期、隔离、停用和可用量不足不得准入。
- 不执行 `git reset --hard`、整体清理或 `git add .`；工作区已有现场证据和物理安全改动必须保留。
- 实现应在从 `origin/feature/wpf-ui-layout-optimization` 派生的独立物料分支/worktree 中进行，避免把本地物理安全提交推入 UI 分支。

## Task 1：物料契约、实体和数据库升级

- [ ] 在 `src/MesControlAgv.Contracts/Materials/` 增加小而稳定的契约：物料类型、样品状态、库存流水类型、样品/耗材导入行、查询结果、扫码结果、库存命令、追溯事件和业务错误码。
- [ ] 在 `src/MesControlAgv.Mes/Entities/` 增加最小实体集合：物料主数据、样品档案、耗材批次/余额、库位、库存流水、扫码事件、任务物料绑定/预占；字段只覆盖设计文档，不引入采购、审批或多级仓库。
- [ ] 在 `MesDbContext` 注册 `DbSet`、长度/精度/唯一索引和必要的外键；同一请求号不能重复产生库存变化。
- [ ] 在 `src/MesControlAgv.Mes/Program.cs` 增加幂等启动升级/建表逻辑，并初始化一个默认仓库；不得删除或重写既有实验数据。
- [ ] 增加实体映射、唯一性、旧数据库升级和默认仓库测试。

完成判据：新数据库可以创建全部物料表；旧数据库启动后既有实验计划、任务和审计仍可读取；重复请求号有唯一约束或等价保护。

## Task 2：MES 物料服务、扫码和库存 API

- [ ] 新增 `src/MesControlAgv.Mes/Services/MaterialManagementService.cs`，集中实现登记、导入提交、扫码解析、入库、移库、调整、查询和追溯；不在 Endpoint 中复制库存规则。
- [ ] 将余额和不可变流水写入同一事务；实现 `available = onHand - reserved`、过期/隔离过滤、负数保护、幂等重放和状态冲突错误。
- [ ] 新增 `src/MesControlAgv.Mes/Endpoints/MaterialManagementEndpointRouteBuilderExtensions.cs`，注册查询、导入预览/提交、扫码、库存命令和任务绑定能力；错误返回稳定的业务码和可显示说明。
- [ ] 在 `Program.cs` 注册服务并映射端点。WPF 不接触厂商 URL，扫码来源只记录手工/键盘枪/接口标签。
- [ ] 覆盖样品/耗材导入幂等、未知/重复条码、入库/移库、隔离/过期、预占/释放/消耗、库存不足和追溯时间线 API 测试。

完成判据：只调用 MES API 即可完成一条样品和一批耗材的登记、入库、移库、查询和追溯；任何失败不会产生半条库存流水。

## Task 3：实验任务预占与使用记录联动

- [ ] 在现有实验排程服务（`ExperimentSchedulingCommandService` 及其持久化/运行生命周期）中接入物料服务：任务准入时解析已登记样品并检查方案耗材需求，成功后建立绑定和预占。
- [ ] 在取消、反排程、失败或释放路径调用释放预占；保持现有实验排程审计和幂等语义，不改变设备控制边界。
- [ ] 增加一个只记录使用/消耗的后端命令或内部服务入口，记录任务、样品编号、进样位置和消耗流水；该入口不得调用离子色谱或其他设备写接口。
- [ ] 任务草稿仍允许未解析样品；准入时返回明确的未登记、不可用、过期/隔离或库存不足原因。历史任务按旧逻辑读取。
- [ ] 增加准入成功/失败、预占释放、重复准入和消耗记录测试，确认取消不发生错误扣减。

完成判据：排程准入只能使用可用样品和库存；取消/失败可恢复可用量；实际使用记录才减少 `onHand`。

## Task 4：WPF 客户端、导入和物料管理页面

- [ ] 在 `IMesClient`/`MesClient` 增加物料查询、导入、扫码、库存命令、追溯和任务绑定方法；保持现有 Fake/离线客户端的默认实现可编译。
- [ ] 复用 `TabularFileReader` 的 CSV/XLSX 读取方式，新增轻量样品/耗材导入解析模型：预览逐行错误、条码幂等提示、通过行提交；不把物料字段加入实验流程编辑器。
- [ ] 新增 `src/MesControlAgv.Wpf/Materials/` 下的页面和 `src/MesControlAgv.Wpf/ViewModels/MaterialManagementViewModel.cs`，只提供“样品”“耗材库存”“扫码与追溯”三个切换页。
- [ ] 在 `MainViewModel`、`MainWindow.xaml` 和必要的资源/命名空间中注册与排程同级的“物料管理”一级菜单；页面默认不展示复杂仓库配置或设备写操作。
- [ ] 样品页提供新增/扫码登记/批量导入/追溯；耗材页提供扫码或手工入库、批量导入、移库、预占/释放、调整；追溯页提供单输入框、识别结果、允许动作和只读时间线。
- [ ] 实验任务/任务导入页面仅显示样品编号和物料校验结果，不显示仓库流水字段；明确展示未知码、重复码、过期/隔离和库存不足错误。
- [ ] 增加 WPF ViewModel、导入预览、HTTP 契约、导航绑定和错误提示测试。

完成判据：不连接真实设备时，WPF 可以通过 MES 完成导入、扫码查询、入库/移库和追溯；导航与现有页面一致，既有 UI 测试不回归。

## Task 5：集成验证、审查和交接

- [ ] 运行新增及受影响的 MES/WPF 定向测试，检查数据库启动升级和幂等行为。
- [ ] 运行 `dotnet test MesControlAgv.sln -m:1`；如运行中的服务锁定程序集，记录锁定原因并至少完成可用项目的 Release 构建，不终止或清理用户进程。
- [ ] 运行 Release 构建、`git diff --check`，确认没有厂商写接口调用、没有直接数据库访问和没有把用户现场证据加入提交。
- [ ] 进行设计文档中的六步手工验收，保存必要的测试摘要；完成代码审查后再决定推送到独立 UI/物料分支，暂不合并主分支。

## 完成判据

1. 样品和耗材可导入、扫码、入库/移库并按条码/批号/任务追溯。
2. 任务准入正确预占，取消/失败释放，使用记录才消耗；所有写操作幂等且有审计。
3. WPF 有独立的简洁物料管理模块，实验流程页面不增加仓库字段。
4. 旧数据库和现有排程、设备只读功能保持可用，未新增进样器真实写操作。
5. 定向测试、全量测试（或明确记录的锁定例外）、构建和代码审查完成。
