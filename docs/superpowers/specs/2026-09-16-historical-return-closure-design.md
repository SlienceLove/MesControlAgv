## 推荐设计

给现有独立人工核销增加一个明确选择的“关联后续成功返航”分支。保持原“源站空闲、全路段404”分支的行为不变；不能自动根据 AGV 已不在源站就改用新分支。

新分支必须同时满足：

1. 请求由有核销权限的操作者提交，包含新 requestId、原因和明确的后续返航 ID。
2. 原任务为已消费许可的独立 Unknown；禁止使用 workflow-linked 任务。
3. MES 核实后续任务是另一条已消费许可、已到站的独立记录，创建/派发晚于原任务，且 AGV、源站、目标站、完整路径及地图身份一致。请求不得自带成功状态来代替服务器证据。
4. Adapter 独立验证原任务身份、完整路径和 Unknown 状态；按关联 ID 加载自己的后续任务记录，确认同车同路径、明确 arrived；不单凭 MES 声明接受。
5. 重新读取原任务全部精确路段，每段恰好一条明确404；新鲜无过滤任务状态没有活动、暂停、排队或不明任务，包括非 GUID 的活动 ID。
6. 当前位置必须是两条任务的共同目标 LM1，且当前地图身份与被核对路径对应；这个分支不允许任意站点核销。
7. 复用现有串行门禁和双层持久化审计。原任务变为 `manually_closed`，保留 LastError、原始路线及已有关联；审计保存关联后续任务及新鲜证据。
8. 重复相同请求只返回已有结果，冲突请求拒绝；MES 回执丢失可从 Adapter 已持久化处置恢复。新增可选关联字段在未提供时不改变旧请求的序列化结果，保证历史请求幂等兼容。

核销本身不发送导航、停止、取消或控制权释放。核销成功后，再通过已有 MES 释放入口用新请求执行一次控制权释放并回读 `none`。

- 正例：原任务404、目标站空闲、双方均有匹配的后续成功记录；只核销原任务，无设备控制写入。
