# 中控 WPF 自动启动本机 MES 设计

## 目标

中控电脑上的 WPF 是现场主入口。启动 WPF 时，自动启动同一台电脑上的 MES，使 WPF 不再把 MES 当作已经存在的外部 physical 服务；同时为控制电脑上的 ShineLab/离子色谱客户端提供可访问的 TCP 服务。

## 已确认的现场拓扑

- 中控电脑有线网卡：`192.168.10.11`
- 控制电脑有线网卡：`192.168.10.108`
- 两台电脑通过有线直连，已可互相 ping 通
- 中控电脑内置 Wi-Fi 连接 Shine 网络
- 中控电脑 USB Wi-Fi 连接现场 AMR 网络
- 本次离子色谱通讯只需要中控与控制电脑之间的有线网络，不要求控制电脑接入 AMR 网络

## 目标数据流

```text
控制电脑 ShineLab/离子色谱客户端
        │ TCP 5500
        ▼
中控电脑 MES / ShineLab TCP Server
        │ HTTP 5145
        ▼
中控电脑 WPF
```

MES 的 HTTP 服务监听 `0.0.0.0:5145`，ShineLab TCP 服务监听 `0.0.0.0:5500`。WPF 在中控本机通过回环地址访问 MES；控制电脑客户端使用 `192.168.10.11:5500`。

## 启动行为

1. WPF 读取启动配置并识别为“本机 MES 托管模式”。
2. WPF 检查本机 MES 健康端点；若已有健康服务，则复用它，不重复启动。
3. 若 MES 未运行，WPF 启动本机 MES 子进程，传入 HTTP 监听地址/端口和 ShineLab TCP 启用配置。
4. WPF 等待 MES 健康检查通过后，再创建 MES 客户端和主窗口。
5. WPF 关闭时只停止由本次 WPF 启动并持有的 MES 子进程；外部已存在的 MES 不得被停止。
6. 不因 WPF 启动自动启动 Adapter、AGV、机械臂或仪器写入服务；现场控制服务仍保持独立和默认安全边界。

## 配置边界

- WPF 的 MES 客户端地址与 MES 的监听地址分离：客户端可使用 `http://127.0.0.1:5145/`，服务端监听 `http://0.0.0.0:5145`。
- ShineLab TCP 配置启用，监听地址为 `0.0.0.0`，端口为 `5500`。
- 本机托管开关必须显式可识别，避免把任意 physical 外部部署误判为可由 WPF 管理。
- 若 `5145` 已被占用但健康检查失败，启动应明确报错，不杀掉未知进程。

## 失败与安全处理

- MES 在启动超时、退出或健康检查失败时，WPF 显示明确的启动失败原因，并不显示为普通“设备离线”。
- 端口冲突、缺少 MES 运行文件、配置无效都必须在启动窗口中可见。
- 服务启动只涉及 MES 和 ShineLab TCP 接收端；不打开串口、不发送设备写命令、不启动 AGV/机械臂动作。
- Windows 防火墙放行由部署步骤处理，不由应用静默修改系统防火墙规则。

## 验收标准

- 从干净状态启动中控 WPF 后，`5145` 有 MES 监听，`5500` 有 ShineLab TCP 监听。
- WPF 状态页不再显示 `127.0.0.1:5145` 拒绝连接。
- 控制电脑执行 `Test-NetConnection 192.168.10.11 -Port 5500` 返回 `TcpTestSucceeded : True`。
- 已经运行的 MES 被 WPF 复用，WPF 退出不会停止它。
- MES 启动失败时不启动任何 AGV、机械臂或仪器写入操作。
- 现有 simulator 模式行为保持不变。
