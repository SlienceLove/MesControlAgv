# 开盖分液单步骤正式业务链设计

日期：2026-09-17

## 1. 目标

将已经通过真机验收的开盖分液工作流 v2 接入现有实验方案、实验任务、排程和运行准入链路，完成一次从正式业务入口发起并由真实设备执行的端到端验收。

本阶段验证的不是新的厂家协议能力，而是中控已有业务对象能否正确承接已经验证的设备工作流：

```text
已发布工作流
  -> 单步骤实验方案
  -> 实验任务
  -> 排程与工作站资源预留
  -> 运行准入与资源租约
  -> 正式工作流运行
  -> 开盖分液工作站单次启动
  -> 任务、排程和资源状态收口
```

## 2. 已确认基线

- 隔离工作区：`D:\Project\Github\Mes-worktrees\sample-workstation-http-readonly`
- 分支：`feature/sample-workstation-http-readonly`
- 开盖分液 Workflow ID：`5d409b9b-45fc-46e9-bd4f-46868ddefbcf`
- 使用版本：`2`
- 工作流结构：开始 -> 开盖分液 `TEST-001` -> 结束
- 工作站设备 ID：`SAMPLE-WORKSTATION-01`
- 厂家设备编号：`CYC-001-1000`
- 厂家服务：`http://192.168.200.157:8082/Service/`
- 正式工作站节点：`sample-workstation.execute-existing-task`
- 所需能力：`sample-workstation.start-existing-task`

工作流 v2 已经完成无人工门禁真机闭环，并验证冷态首次任务可由厂家程序自动初始化后继续执行。本设计不改变该节点的单次发令、Running 证据和只读恢复语义。

## 3. 方案选择

采用现有的单工作流实验任务准入链路，不新增专用“一键开盖分液”入口，也不启用实体设备多步骤复合运行。

原因：

- 单步骤实验方案已经由现有 `ExperimentPlan`、`ExperimentJob`、`ScheduleEntry` 和运行准入服务支持。
- 准入服务能够创建固定版本的 `WorkflowRun` 和独占资源租约。
- 正式工作站 Worker 已经能够执行 v2 中的开盖分液节点。
- 该路径可以最小成本验证真实业务入口，而不引入尚未确定的上下游设备和任务表格式。

## 4. 业务对象设计

### 4.1 实验方案

新建一版用于现场验收的单步骤实验方案，建议名称为 `开盖分液单步骤正式方案-20260917`。

方案只包含一个步骤：

| 字段 | 值 |
| --- | --- |
| 步骤名称 | 开盖分液 |
| Workflow ID | `5d409b9b-45fc-46e9-bd4f-46868ddefbcf` |
| Workflow Version | `2` |
| 预计时长 | 10 分钟 |

预计时长只用于排程显示和冲突计算，不参与设备完成判定。设备完成仍以工作站节点观察到本轮 Running 后，再同时满足任务 Completed、设备 Idle/0、错误码 0 为准。

方案声明一个独占资源要求：

| 字段 | 值 |
| --- | --- |
| ResourceType | `workstation` |
| ResourceId | `SAMPLE-WORKSTATION-01` |
| Quantity | `1` |
| Exclusive | `true` |

方案按现有流程完成草稿、校验和发布。发布版本不可变；如果需要调整，应创建下一版方案，而不是修改已发布版本。

### 4.2 实验任务

从已发布方案创建一个现场验收任务：

- `SampleBatchId` 必填，用于中控追溯本次验收批次。
- `SampleId` 可选，用于记录现场样品标识。
- 方案版本和工作流版本在创建任务时固定。
- 本阶段不把 `SampleBatchId` 或 `SampleId` 映射为厂家任务号、条码或分液参数。
- 厂家任务号继续使用工作流 v2 节点中已经验证的 `TEST-001`。

任务参数不得覆盖工作站节点的 `taskNo`。未来任务表导入完成后，再单独设计任务创建结果如何绑定工作流运行参数。

### 4.3 排程与资源

任务排入当前现场测试窗口，计划时长使用方案的 10 分钟估计值。排程必须明确选择 `workstation/SAMPLE-WORKSTATION-01`。

排程阶段创建计划预留；点击“运行准入”后才创建实际运行租约。计划预留不能被当作设备正在运行的证据。

## 5. 执行数据流

1. 操作员在 WPF“实验方案”中选择工作流 v2，创建、校验并发布单步骤方案。
2. 操作员在“任务排程”中基于已发布方案创建实验任务，填写样品批次标识。
3. 操作员为任务安排测试时间和 `SAMPLE-WORKSTATION-01` 独占资源。
4. 发令前只读核对工作站 Online、Idle/0、错误码 0，且 `TEST-001` 不处于 Running。
5. 操作员选择任务并执行“运行准入”。该动作是正式业务发起点；原默认隐藏联调入口不参与本次执行。
6. MES 固定方案和工作流版本，创建一个正式 `WorkflowRun`，并为工作站创建一个活动资源租约。
7. `WorkflowSampleWorkstationWorker` 认领开盖分液节点，只发送一次 `StartTask(TEST-001)`。
8. Worker 必须观察到本轮 Running 证据，之后再等待 Completed、Idle/0 和错误码 0 三项一致。
9. 工作流完成后，实验任务更新为 Completed，排程更新为 Completed，工作站活动租约被释放。
10. WPF 运行监控显示节点执行证据；排程时间轴显示实际设备活动，不用计划时间冒充实际时间。

## 6. WPF 操作边界

本阶段使用现有正式页面：

- “实验方案”：建立、校验、发布单步骤方案。
- “任务排程”：创建任务、选择资源、安排时间、执行运行准入。
- “流程运行监控”：查看工作流节点、设备操作和完成时间。
- “资源时间轴”：查看计划预留、活动租约和实际设备活动。

原开盖分液联调入口继续保留但默认隐藏。“现场 Move 验收许可”继续完全隐藏。

只有现有界面缺口实际阻断上述链路时，才做最小修复。不得为了本阶段新增第二套实验启动模型或工作站专用业务页面。

## 7. 状态与异常处理

### 7.1 准入前

- 方案未发布、资源未配置、任务未排程或设备能力不匹配：拒绝运行准入，不创建工作流运行，不发送设备命令。
- 工作站暂时离线、非 Idle、错误码非 0、任务状态不可读或 `TEST-001` 已在运行：节点保持 Ready 并继续只读检查，不发送启动命令。设备 ID、任务号或能力配置无效等不可恢复的配置错误按现有规则进入 Failed，同样不发送启动命令。

### 7.2 发令后

- 启动明确拒绝且可以证明没有执行：节点 Failed，停止后续流程。
- 启动响应超时、断线或结果不能证明未执行：节点 Unknown，不自动重发。
- 未观察到本轮 Running：旧 Completed 不能完成本轮节点，观察窗口到期后进入 Unknown。
- 已观察 Running，但最终状态不一致或超过完成时限：进入 Unknown，停止后续流程。
- 不发送远程停止命令。用户关闭监控界面只停止界面观察，不表示设备停止。

### 7.3 业务状态收口

- 工作流 Running 时，实验任务应进入 Running。
- 工作流 Completed 时，实验任务和排程应进入 Completed，并释放活动租约。
- 工作流 Failed 或 Cancelled 时，实验任务按现有生命周期映射并释放租约。
- Unknown 不得被显示成成功，也不得自动创建替代工作流或再次启动工作站；在人工核销前保留现有占用证据，不因预计结束时间到达而自动释放租约。

## 8. 配置策略

继续使用现场隔离运行目录中的配置覆盖，不把现场 IP、控制开关或 Worker 开启状态写入默认开发配置。

现场执行时必须同时满足：

- Adapter 工作站 `Enabled=true`、`ControlEnabled=true`。
- Adapter `EquipmentNo=CYC-001-1000`。
- Adapter `BaseUrl=http://192.168.200.157:8082/Service/`。
- MES Profile 包含启用且允许控制的 `SAMPLE-WORKSTATION-01`，并声明 `sample-workstation.start-existing-task`。
- `WorkflowSampleWorkstationWorker.Enabled=true`。
- `ExperimentCompositeRuntimeWorker` 不用于本阶段实体运行。

自动化测试不得访问 `192.168.200.157`，也不得启动本地现场服务或真实设备命令。

## 9. 实施顺序

### 阶段 1：静态核对

- 核对隔离分支和工作区洁净状态。
- 核对工作流 v2 仍为已发布且节点配置为 `TEST-001`。
- 核对当前业务链代码可以从单步骤方案准入到正式工作流运行。
- 补充自动化测试，覆盖本设计要求但当前尚未覆盖的状态投影或 WPF 操作缺口。

### 阶段 2：非真机演练

- 继续使用已归档且包含工作流 v2 的现场隔离运行数据目录，在其中创建并发布单步骤方案；如果目标目录中缺少该固定 ID/版本，先按归档定义恢复同一工作流版本，不改用一个未验证的新工作流 ID。
- 创建任务和排程。
- 先执行不产生设备操作的查询和页面核对。
- 如果需要验证业务对象创建，可在明确的模拟或 Dry Run 路径完成；Dry Run 不作为真机验收结果。

### 阶段 3：真机验收

- 现场确认厂家程序已监听。
- 只读核对设备基线。
- 从 WPF“运行准入”发起一次正式任务。
- 观察业务对象、工作流、设备操作和真实设备状态完整收口。
- 不在同一验收轮次制造断线、停止或异常。

### 阶段 4：归档

- 记录方案、任务、排程、工作流运行、节点执行和设备操作 ID。
- 记录 Running 与 Completed 时间、启动操作计数和资源租约释放证据。
- 更新开盖分液交接文档，但不在本阶段合并主工作区或整理分支。

## 10. 自动化验证

实施阶段至少运行：

- 实验方案与排程契约测试。
- 实验排程持久化和命令 API 测试。
- 单步骤运行准入及资源租约生命周期测试。
- 工作站正式 Worker 测试。
- WPF 实验方案、任务排程和运行监控定向测试。
- 受影响项目的构建。

测试需明确覆盖：

- 单步骤方案不会进入复合运行拒绝路径。
- 准入只创建一个固定版本的工作流运行。
- 工作站资源租约与该工作流运行关联。
- 工作流 Running/Completed 能投影到实验任务。
- 完成后排程收口并释放租约。
- 实际设备活动能关联实验任务、工作流和 `SAMPLE-WORKSTATION-01`。

## 11. 真机验收标准

以下条件全部满足才算本阶段完成：

1. 从已发布单步骤实验方案创建一个实验任务并成功排程。
2. 运行准入成功创建且仅创建一个正式 `WorkflowRun`。
3. 本轮只产生一条工作站启动设备操作，没有自动重试或重复启动。
4. 设备状态证据包含本轮 Running，随后为任务 Completed、设备 Idle/0、错误码 0。
5. 开盖分液节点和工作流均为 Succeeded/Completed。
6. 实验任务为 Completed，排程为 Completed。
7. `workstation/SAMPLE-WORKSTATION-01` 的活动租约已释放。
8. WPF 运行监控能看到节点执行和完成时间。
9. 资源时间轴能看到本轮实际设备活动，并能与计划预留区分。
10. 现场执行 ID、状态时间和单次发令证据已经归档。

## 12. 非目标与后续边界

本阶段不包含：

- 多步骤实体实验方案自动编排。
- AGV、机械臂、检测仪器等上下游节点接入。
- 厂家任务创建、轨迹写入或任务表导入。
- 将样品编号自动映射为厂家条码或任务号。
- 运行中暂停、停止或远程取消。
- 自动重试工作站启动请求。
- 分液精度、液路或实验结果质量验收。
- 主工作区合并、分支清理或历史提交整理。

完成本阶段后，再根据已经明确的上下游设备和数据格式设计多步骤实体复合运行。任务表导入仍遵循“只创建任务，不隐式启动”的既定边界。
