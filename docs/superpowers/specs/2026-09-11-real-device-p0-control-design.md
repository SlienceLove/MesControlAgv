# 四类实体设备真实控制 P0 设计

日期：2026-09-11  
状态：已获项目方确认，待文档审阅后进入实施计划  
目标分支：当前功能基线；WPF UI 优化分支暂缓

## 1. 目标与验收口径

两周内不要求连续批量、无人值守或长期稳定性验收，P0 的硬目标是完成一次可重复的真实单样本闭环：

```text
WPF 发起运行
  -> MES 建立运行、设备操作和审计记录
  -> AGV 真实到站
  -> AUBO 真实加载/运行批准程序
  -> 开盖分液工作站真实初始化、建任务/导入任务并启动
  -> 两台离子色谱分别完成一次真实执行
  -> 每台设备回传任务号、状态、错误和结果
  -> MES 汇总并生成可归档结果报表
  -> WPF 展示完整时间线和最终结果
```

验收必须覆盖四类设备的真实写操作或真实任务启动，不得用 Simulator、历史截图或只读快照替代。允许在现场由操作员确认安全条件，并允许人工处理未确认结果；不要求本阶段实现连续批量调度。

如果现场实际设备数量超过当前配置，设备清单、设备 ID、网络地址和能力必须在部署配置中显式增加；本设计不把多台设备隐式合并为一个逻辑设备。

## 2. 非目标与硬边界

- 暂不做 WPF 视觉重构、布局优化或新导航架构；只补足真实控制所需的最小页面绑定和结果展示。
- 不在未获得厂家正式字段、响应和动作映射前猜测离子色谱写协议。
- 不绕过 WPF -> MES -> Adapter/仪器网关分层直接从 WPF 访问厂家端口。
- 不把开盖分液 HTTP 接口并入 D160+ 串口网关；它保持独立 Adapter 模块。
- 不自动重发任何可能已经到达设备的写操作。超时、断线、响应不完整均进入 `Unknown`，先查询和人工对账。
- 不把历史 AGV/AUBO 验收记录当作当前授权；每次现场运行都必须有新的安全预检和授权记录。

## 3. 总体架构

```text
WPF 控制中心
  | 业务命令、运行监控、结果报表
  v
MES
  | 工作流、OperationId、资源/联锁、审计、Unknown 对账
  +--> AGV Adapter (vendor-tcp)
  +--> AUBO Adapter (WebSocket JSON-RPC 9012)
  +--> SampleWorkstation Adapter (厂家 HTTP)
  +--> Ion Chromatography Gateway/Adapter (两台独立实例)
                                      |
                                      +--> ShineLab/YLoop 或厂家模块协议
                                      +--> D160+/SHA-18i 真实设备
```

职责边界：

- WPF 只提交经过权限校验的业务命令并读取 MES 投影；不拼接厂家报文。
- MES 负责流程编排、跨设备前置条件、互斥资源、设备操作生命周期、结果关联和审计。
- Adapter 或仪器网关负责连接、协议编码、单写入队列、超时、设备原始证据和幂等保护。
- 每个真实设备操作都有稳定的 MES `OperationId`、运行 ID、节点 ID 和可选厂家任务号；这些字段贯穿请求、响应、轮询和报表。

## 4. 四类设备设计

### 4.1 AGV

沿用当前已验证的 `vendor-tcp` 驱动和现场端口模型。P0 只支持单车、低速、单段或少量连续段的受控流程：

1. 新鲜只读预检：在线、定位完成、地图名称/版本/MD5/有向边、无急停/阻挡/故障、当前任务为空。
2. 取得本次会话控制权并再次预检。
3. 派发单个到站任务，轮询 `moving/arrived/failed/unknown`。
4. 到站后释放控制权并写入 MES 证据。

实体配置必须从 `read-only-preflight` 切换到经现场批准的标准模式，启用 `AcquireControl` 和现场导航准入；不得仅通过 WPF 开关改变运行模式。AGV 的暂停、取消、控制权释放和异常路径沿用现有 fail-closed 策略。

### 4.2 AUBO 机械臂

沿用现场验证的 WebSocket JSON-RPC `192.168.1.102:9012`，以批准工程目录为唯一程序来源。P0 支持：

- 读取在线、机器人模式、安全模式、运行模式、当前工程和程序目录；
- 在现场授权、程序白名单和安全状态满足后，单次 `load`、单次 `run`、单次 `stop`；
- 运行后轮询 `Running`，停止后连续稳定观察到 `Stopped` 才完成；
- 任一写入响应不确定时将操作标记为 `Unknown`，由人工查询当前工程和运行态后收尾。

当前 Adapter 侧 `AuboArm:Enabled/ControlEnabled`、MES `WorkflowAuboWorker` 和物理就绪监督器默认关闭。实施时只在隔离现场配置中打开，并为每次运行保存新鲜预检、授权人、程序名和设备 epoch。

### 4.3 开盖分液工作站

依据 `res/开盖分液工作站Http接口文档V1.0.pdf`，扩展现有 `SampleWorkstationAdapterModule`。厂家接口内部虽然全部使用 HTTP GET/POST 混合方式，但中控对外只暴露规范化 POST 命令。

P0 最小接口：

- 只读：`GetInstrumentStatus`、`GetErrorInformation`、`GetTaskInformationList`、`GetTaskDetails`、`GetTaskState`；
- 初始化：`Init`；
- 建任务：优先实现 `AddExperimentalTask` 和必要的 `AddTaskTrajectoryParameter`；如果现场只支持模板方式，则实现 `GetExperimentalTaskTemplate`/`ImportExperimentalTask` 的受控导入路径；
- 启动：`StartExperiment`；
- 收尾：轮询 `GetTaskState` 和 `GetTaskDetails`，必要时记录厂家任务号和完成时间；
- 仅在厂家确认语义后开放 `DeleteTaskRunState`、`DeleteTaskRecord`、`ArmAvoidance` 或复位操作。

现场配置必须提供真实 IP、端口（文档出现 `8082` 和 `8808` 两种示例，不能猜测）、基础路径 `/Service/`、`EquipmentNo` 和认证/防火墙要求。所有模板、物料、轨迹和溶剂参数必须来自批准版本；操作员不能在生产命令中直接输入底层坐标、速度或夹爪参数。

工作站状态机采用：

```text
Offline -> Connecting -> Uninitialized -> Initializing -> Idle
Idle -> Preparing -> Ready -> StartPending -> Running -> Completed
任意非终态 -> Faulted / Unknown / ManualInterventionRequired
```

### 4.4 两台离子色谱

两台仪器必须是两个独立的设备配置、连接会话和结果关联键，不得共享单例任务状态。P0 采用可插拔协议适配：

- `CIC-D160+` 现有 Modbus 串口驱动继续负责只读身份、压力、温度、流量、电导率和泵/抑制器状态；
- ShineLab/YLoop TCP 现有 LF-JSON 监听器继续负责现场连接、认证和状态接收；
- 厂家模块交付后新增正式 `Config`、`Command`、进样、暂停/停止、结果和错误映射，不改变 MES 上层任务契约；
- 在厂家字段和动作映射确认前，禁止发送任何猜测的 `Config`、`Command`、进样或停止报文；
- 每台仪器必须能完成一次“方法/样品/通道 -> 启动 -> 运行状态 -> 结果/文件 -> 任务完成”的闭环，结果至少包含设备 ID、样品批次、方法版本、通道、厂家任务号、原始结果引用、解析结果和时间戳。

当前现场 YLoop 数据已证明 TCP 连接层可用，但空 `equipmentCode/strCode` 和 `status=99` 的含义仍需厂家确认。该问题是离子色谱 P0 的外部关键路径，不得用 fallback 编号直接进入生产控制。

## 5. MES 工作流与联锁

增加通用设备操作执行器边界，至少包含：

- `AgvMoveStepExecutor`；
- `AuboProgramStepExecutor`；
- `SampleWorkstationStepExecutor`；
- `IonChromatographyStepExecutor`，支持按设备 ID 选择两台仪器。

每个执行器遵循相同顺序：

1. 校验已发布流程、设备能力、资源租约、操作员权限和当前运行授权；
2. 持久化 `DeviceOperation` 和 `OperationId`；
3. 执行一次真实命令；
4. 通过只读状态或厂家任务查询确认结果；
5. 持久化成功、失败、取消或 `Unknown`，同时保存原始响应摘要；
6. 只有明确完成且设备回到安全状态，才允许下一个依赖步骤。

关键联锁：

- AGV 未到目标站点或仍有活动任务时，不得启动工作站或机械臂步骤；
- 工作站运行或机械臂未回安全位时，不得派发 AGV 离站；
- 离子色谱未处于允许进样状态时，不得启动进样；
- 检测到外部任务、设备状态未知、任务号不一致或结果缺失时，流程停止在 `Unknown/ManualInterventionRequired`；
- 不允许通过刷新、重启或 WPF 重复点击隐式重发同一物理写操作。

## 6. WPF 最小改动

UI 优化分支暂缓，只实现真实 P0 所需的最小功能：

- 设备选择：两台离子色谱和开盖分液设备必须能明确选择并显示设备 ID；
- 运行启动：提交批次、方法、样品位/通道、工作站任务参数和现场授权信息；
- 运行监控：按设备显示 `OperationId`、厂家任务号、状态、时间、错误和当前阻塞原因；
- Unknown 处理：显示“查询/人工确认”入口，禁止自动重试；
- 结果报表：支持按运行 ID 导出 JSON/CSV 或现有报表格式，包含所有设备步骤、结果引用和审计信息。

WPF 不直接访问真实设备。即使某个设备暂时没有完整控制能力，页面也必须明确显示“只读”“控制未授权”或“协议待厂家确认”，不能显示为空闲并诱导操作员继续。

## 7. 错误处理和数据模型

统一设备操作状态：

```text
Queued -> Preparing -> StartPending -> Running -> AcquiringResult
AcquiringResult -> Completed
任意非终态 -> Failed / Cancelled / Unknown / ManualInterventionRequired
```

`Unknown` 的触发条件包括：请求超时、连接在写入后断开、响应无法解析、厂家任务号无法关联、重启后无法证明上一动作结果。进入 `Unknown` 后：

- 不自动重试写操作；
- 继续允许只读查询、任务列表和结果对账；
- WPF 必须要求操作员明确选择“已完成/失败/继续人工处理”；
- 所有人工决定写入审计记录。

设备原始报文只保存脱敏摘要、长度、方向、请求/响应哈希和结果文件引用；不得把现场凭据写入仓库。

## 8. 实施顺序与外部依赖

### 第 0～1 天：协议和现场输入冻结

- 固定 AGV 最新地图和现场控制授权；
- 固定 AUBO 程序白名单、当前工程和安全状态；
- 从工作站厂家确认真实 IP/端口、`EquipmentNo`、`Init`、建任务、启动和结果接口样例；
- 从离子色谱厂家取得两台设备的正式设备编号、`equipmentCode/strCode`、状态码、Config/Command、结果和停止语义；
- 确认结果报表字段和归档目录。

### 第 2～4 天：真实只读基线

四类设备全部形成新鲜、隔离、可追溯的只读证据；完成设备目录、在线状态、任务列表、当前工程、仪器状态和协议版本登记。任何一台无法只读稳定连接时，不进入写入阶段。

### 第 5～8 天：单设备写入

按 AGV、AUBO、工作站、离子色谱的顺序逐台完成一次受控写入/任务启动和结果确认，每次只发送一次写命令，形成独立 OperationId 和证据包。

### 第 9～11 天：跨设备串行流程

在已有单设备证据基础上，接入 MES 工作流执行器和联锁，完成一次从 AGV 到站到两台离子色谱结果归档的串行流程。先人工确认设备交接，再逐步减少人工介入。

### 第 12～14 天：WPF 验收和收尾

完成 WPF 运行、监控、Unknown 处理和报表导出；执行一次断线/超时只读对账演练、一次错误任务演练和一次正常全流程验收。整理发布配置、日志、数据库和证据清单。

如果第 1 天结束时厂家仍未提供离子色谱正式写协议，四设备真实闭环无法按期承诺；此时必须由项目方决定延期或接受“AGV/AUBO/工作站真实执行 + 离子色谱只读”的降级范围，不能以猜测协议替代验收。

## 9. 验收标准

### 功能

- WPF 能创建并启动一个真实运行；
- AGV、AUBO、开盖分液和两台离子色谱均产生真实执行证据；
- 每一步都能关联 MES 运行 ID、节点 ID、`OperationId` 和厂家任务号；
- 两台离子色谱均回传结果或结果文件引用；
- WPF 能显示完整时间线并导出结果报表。

### 安全和一致性

- 所有设备写入均单次发送，超时不自动重发；
- 未确认状态显示为 `Unknown`，不会被归类为空闲或完成；
- 设备状态、任务号、结果和报表中的批次号一致；
- 现场安全授权、程序白名单、地图快照和设备配置均有证据；
- 任何未满足联锁的步骤保持 Ready/Blocked，不向设备发送命令。

### 工程质量

- 现有离线测试保持通过；
- 新增协议编码、状态映射、幂等、超时和结果解析测试；
- 真实验收使用独立数据库和运行目录；
- 发布前工作树、构建版本、配置哈希和证据清单可追溯。

## 10. 当前已知阻塞项

1. 两台离子色谱厂家模块和正式写协议尚未交付；这是 P0 外部关键路径。
2. 开盖分液协议文档虽然在 `res` 中，但真实 IP/端口、设备编号、认证方式、建任务字段和结果样例尚未确认。
3. 当前物理配置仍默认关闭 AGV 自动派发、AUBO 控制、工作站控制和物理 Worker；必须通过现场授权流程开启，不能在开发机默认打开。
4. 当前分支含有现场证据和 UI 相关未整理改动；正式部署前必须重新构建并生成单一版本清单。
