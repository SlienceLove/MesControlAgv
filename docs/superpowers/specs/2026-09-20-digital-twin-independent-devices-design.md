# 设备独立在线与地图参照显示收敛

## 用户需求

数字孪生位置和运动效果已基本认可。现场不会同时启动所有设备，开盖／分液离线不应拖住 AGV 状态及活动显示。截图中辅助标注只在开启“地图参照”时显示，并去掉“正上方俯视”入口。

本次不发设备动作，不变更模型、坐标对齐和自适应动画，不提交或合并。继续使用既有隔离工作区。

## 已核实原因与推荐

WPF `DigitalTwinStatusSession` 已是三个独立读取循环，位姿也有独立来源；保留这些机制并增加离线隔离回归。后台 `PhysicalReadinessSupervisor` 仍串行探测，一台工作站20秒超时会超过其他设备10秒新鲜度窗口，导致在线 AGV 的 Ready 信息反复失效。

推荐后台按设备独立轮询、独立超时与更新。只把全轮刷新改为一次 Task.WhenAll 仍会让下一轮等最慢设备，不能充分隔离；单纯延长新鲜度也不是本次方案。

## 设备状态方案

- 每台配置设备具有独立只读观察循环和单设备并发门闩；后台周期读取与手动刷新复用同一门闩，不对同一设备叠加请求。每次探测使用独立 DI scope，避免并发共用非线程安全依赖。
- 正常设备按自身周期更新并立即发布，不等待其他设备；错误、断线和超时只更新对应设备的状态及错误说明。不能通过其他设备的成功结果替离线设备标为在线。
- 不响应取消的读取只允许一条在途请求，丢弃其超时后的成功结果、观察迟到异常；不阻止其他设备循环，不无限堆积重试任务。服务停止时停止循环并正确释放资源。
- 保留设备独立的新鲜度、稳定窗口、epoch、重连后重新授权和控制准入。AGV单设备路径只使用 AGV就绪条件；涉及开盖／机械臂的原完整流程仍要求其所需设备就绪，不绕过全流程保护，不自动恢复历史任务。
- UI 保留设备实际离线／不可用／读取超时的区别。AGV位姿正常时继续动画；AGV自身数据异常仍按原规则冻结。

## 地图参照方案（推荐显示范围）

“地图参照”默认关闭，点击开关统一控制以下辅助内容：

- 右侧导航小地图；
- 三维地面黑色地图轮廓／扫描点、蓝色规划线、LM站点圈和标签；
- 三维画面左上数据来源说明、左下示意对齐说明及鼠标操作提示。

关闭参照仍显示地面与1m网格、固定设备和AGV模型、AGV实时移动，以及设备上方状态标签。用户已明确确认“对，按这个范围隐藏”。设备状态卡和WPF位置异常提示不隐藏，以免把异常一起藏掉。

“路线开关”仅控制参照开启时是否显示蓝色规划线；关闭地图参照期间操作路线开关不能让线条单独漏出。再次开启参照时恢复路线开关选择，不改位姿同步状态或标定。保留运行范围构图，开关参照不自动转相机。

移除常用工具栏“正上方俯视”按钮及公开top命令入口；保留摆正全景、设备区、鼠标旋转／缩放和聚焦。原正交相机测试可作为内部几何测试保留，但用户界面不再提供俯视模式。标定仍在现有可旋转场景点选，不因此新增自动标定或改变已认可对齐。

## 验证与交付

1. 后台离线测试：工作站长时间无响应／断线，AGV持续多轮获得新鲜Ready且epoch不因其他设备反复变化；设备恢复、手动刷新并发、取消和同设备无重叠；完整流程安全门槛不退化。
2. WPF与原生离线三维：工作站错误时AGV和机械臂各自刷新，AGV连续动画正常；AGV自身过期仍冻结。
3. 地图参照默认关闭、开关所有辅助元素、路线组合状态、不影响移动／设备标签；俯视入口消失；位置对齐、清晰度、已优化动画不变。
4. 相关回归和独立代码审查通过后发布新独立包。后台修复需要切换MES服务才能生效，届时先核对无活动任务、运行包与数据库，另行说明切换；不直接覆盖运行包或为测试关闭真实工作站。
