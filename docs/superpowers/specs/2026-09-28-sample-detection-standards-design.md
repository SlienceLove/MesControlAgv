# 样品检测标准与人工判定设计

日期：2026-09-28
分支：`feature/sample-detection-standards`
状态：用户已确认，首版已实现，待集成

## 目标与边界

用户在中控维护检测方法编号及其检测指标和判定参数；按编号查询标准，对物料台账中的样品人工录入检测值，得到可追溯的逐项及总体判定。首版只处理数值型指标，复用现有物料样品，不创建第二套样品主数据。

参考页提供了“编号、名称、分类、指标、检出限”的交互样例，但其浏览器本地预置数据不是本项目已核实的标准，不自动导入。现有 ShineLab `DetectionMethod` 是设备指令字段，不能将用户维护的方法编号直接写入该字段。

首版不改样品 CSV/XLSX 导入、实验排程、工作流准入、仪器协议、设备任务下发或仪器结果接收。历史样品流转模型不迁移；只有物料台账中具有 `SampleMaterial.SampleId` 的样品参与判定。

## 界面与操作

在现有一级“物料管理”的页签中增加“检测标准”。列表支持按方法编号或名称搜索，展示编号、名称、分类、当前修订号、启用状态及指标数；详情展示每项指标的名称、单位、检出限、合格下限和上限。

用户新建方法时填写编号、名称及至少一个指标。保存即生成不可原地改写的修订版；修改时从当前版复制为下一修订，并带上基础修订 ID，防止过期页面覆盖其他用户已发布的新修订。确认保存后将新修订设为当前启用版。同一方法编号同一时刻最多有一个启用版；停用仅阻止新判定选用，不删除旧版和历史结果。编号查询默认打开启用版，历史修订可从详情查看。编号可能包含斜杠，查询使用 URL 查询参数而非路径段。

现有“样品”页签增加针对选中样品的“检测判定”入口，不扩充每行常驻字段。弹窗中输入或选择方法编号，自动显示该方法当前启用版的指标和规则；用户勾选本次实际检测的指标并填写检测值，预览逐项及总体判定后确认保存。样品详情可查看历次判定及所用标准修订，原有样品导入界面和列保持不变。

## 数据与接口

MES 数据库新增独立的标准修订、指标规则、样品判定及判定明细记录。标准修订保存方法编号、名称、分类、修订号、状态和创建人/时间；每条指标规则保存名称、单位、可空的检出限及合格下限/上限。方法编号在去除首尾空白后不区分大小写；编号与修订号组合唯一。

判定记录引用已有物料样品 `SampleId` 和不可变的标准修订，同时保存样品条码、当时绑定的任务 ID（若有）、操作者、时间、输入值、单位、逐项结论及总体结论。更正结果通过新增记录完成，不覆写原记录。标准后续停用或升版不改变历史判定。

按现有 Contracts → MES 服务/端点 → WPF Client/ViewModel 模式新增标准查询、创建修订、停用、提交判定和查询样品判定历史接口。标准和判定以 MES 数据库为准，不使用 WPF 本地文件或浏览器存储。

## 判定规则

- 数值使用十进制值；上下限均为可选、包含端点，至少有一个限值才能自动判定。两个限值同时存在时下限不得大于上限。
- 检出限与合格限值分开存储。测量值低于已配置的检出限时显示“低于检出限 / 无法判定”，不能仅凭检出限推断合格。
- 至少选择一个指标，且每个选中指标都必须填写合法数值。录入单位必须与指标配置单位一致；首版不做单位换算。缺少值、无效数值或单位不匹配阻止提交；缺少判定限值可以保存为“无法判定”，不能显示“合格”。
- 总体结论只汇总本次选中的指标：任一指标不合格时为“不合格”；全部合格时为“合格”；其余情况为“无法判定”。
- 保存时服务端重新计算结论，不信任客户端预览。不存在的样品或未启用的标准修订须拒绝提交。提交携带请求 ID：相同请求和内容重复提交返回原结果，同一请求 ID 的不同内容返回冲突。

## 验证与后续

测试覆盖编号/修订唯一性、启用版查询、历史版不可改写、上下限边界、低于检出限、缺失规则、单位不匹配、总体判定、持久化回读和样品导入回归。WPF 验证标准查询、新建修订、选样录值、判定预览与历史查看。新 worktree 起点已通过 WPF 760 项、MES 781 项基线测试；功能完成后本分支 MES 790 项、WPF 766 项通过，未运行现场设备动作。

以后接入仪器结果时，另做结果字段与指标规则的显式映射和来源核对；不把现有 ShineLab 原始 `ResultJson` 直接判为合格，也不让检测结论自动触发设备动作。
