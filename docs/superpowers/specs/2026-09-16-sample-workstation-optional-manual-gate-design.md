# 开盖分液人工确认门禁改为可选设计

## 背景与证据

厂家新版已在明确未手动初始化的冷态设备上完成现场验证：中控单次发送已有任务 `TEST-001` 后，厂家主程序先显示“正在进行设备初始化”，随后自动进入实验；接口观察到 Running，最终任务、设备和工作流均 Completed。

本次执行：

- Workflow Run：`2614a47e-baaa-471c-9b63-580c43f0540a`
- Device Operation：`883498e1-1a65-313b-7e50-0e868cec78b2`
- 人工确认备注：`冷态未初始化，验证厂家新版是否自动初始化并启动`
- 启动请求：1 次
- 现场顺序：自动初始化 → 自动实验
- 最终状态：设备 Idle/0、任务 Completed、错误码0、工作流 Completed

因此，开盖分液正式流程不再需要以人工方式确认厂家主程序已经初始化。

## 目标

取消 `sample-workstation.execute-existing-task` 节点必须由 `core.manual-confirmation` 直接前置的发布限制，使正式流程可以直接执行已有任务。

## 设计

- 删除工作站节点的强制人工前置发布规则和对应阻断性校验。
- 保留 `core.manual-confirmation` 节点、MES 人工确认接口以及 WPF 确认/取消操作；流程设计者仍可按需显式加入人工节点。
- 不新增中控远程初始化调用。工作站 worker 继续只调用一次 `StartTaskAsync`，厂家程序负责在需要时自动初始化并继续实验。
- 已发布 v1 保持不变。新增并发布 v2：`开始 → 开盖分液执行 TEST-001 → 结束`。
- v2 不包含人工节点，因此 WPF 运行监控不会显示人工确认操作条。

## 运行语义

现有工作站运行保护保持不变：

- 启动前只读检查设备、错误码和任务状态。
- 单次发送启动请求，不自动重试。
- 必须观察到本轮 Running 后才能接受 Completed。
- 完成仍要求任务 Completed、设备 Idle/0、错误码0一致。
- 超时、断线或无法确认的结果进入 Unknown，并停止后续流程。
- 不增加远程停止、任务创建、任务导入或轨迹写入。

## 错误处理

如果厂家自动初始化失败、只初始化未继续实验或启动结果不明确，沿用现有工作站节点的失败/Unknown 处理，不由中控补发初始化或再次启动。人工确认节点仍可在特殊流程中显式配置，但不作为工作站节点的通用强制门禁。

## 验证

- 发布校验测试：无人工前置的工作站节点可以发布。
- 兼容测试：显式保留人工前置的流程仍可发布。
- 现有工作站 worker、单次启动、恢复和排他测试继续通过。
- 发布 v2 后先确认运行画面无人工确认条，再执行一次单次真机闭环。

## 非目标

- 不删除 WPF 通用人工确认功能。
- 不修改已发布 v1。
- 不把初始化能力暴露为新的中控工作流节点。
- 不改变其他设备或节点的人工门禁规则。
