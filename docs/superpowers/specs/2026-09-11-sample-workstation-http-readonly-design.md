# 开盖分液工作站 HTTP 只读通讯设计

日期：2026-09-11  
范围：内部实验阶段，先为真实设备联通测试提供最小可用的只读通讯能力。

## 目标

在不发送任何会改变设备或任务数据的请求前提下，补齐 `res/开盖分液工作站Http接口文档V1.0.pdf` 中的 HTTP 查询接口。调用方可以读取真实设备的状态、错误、任务和协议目录/模板响应，为后续现场核对提供基础。

## 非目标

本阶段不实现 `Init`、`ArmAvoidance`、任务创建、轨迹添加、启动、模板导入、删除或其他写操作；不做 WPF 页面、复杂状态机、操作审计、自动重试和模板文件解析。

## 方案

沿用现有 `MesControlAgv.Adapter` 的 `SampleWorkstation` 模块和 `VendorSampleWorkstationHttpClient`。厂家请求统一使用 HTTP GET，基础地址和 `EquipmentNo` 来自配置，响应统一读取 `{ Code, Data }` 包络。已有的状态、错误、任务列表、任务详情和任务状态接口继续使用强类型 DTO。

新增一个轻量的只读协议操作映射：用固定操作名映射到协议中的工作流、物料类型、平台布局、移液参数、溶剂参数及实验/参数模板路径。目录和模板数据不提前猜测字段，使用原始 JSON `Data` 返回，并附带操作名、业务码和读取时间。未知操作名不向厂家发请求。

Adapter/MES 仅增加最少的查询入口，便于 curl 或现有客户端验证真实设备；不开放厂家原始 URL，也不注册写操作路由。查询参数只覆盖协议实际使用的 `key`、日期、分页和 `taskNo` 等字段。

## 错误与测试

- HTTP 非成功状态、厂家 `Code` 非 200、无效 JSON 或缺少 `Code`/`Data` 直接报告错误。
- 请求超时直接返回超时错误，不自动重试。
- 单元测试使用假的 `HttpMessageHandler`，验证 URL、query、GET 方法、典型 `Code/Data` 响应和失败响应。
- 完成后运行 Adapter 测试，并运行受影响的 MES 测试；不连接现场 IP。

## 交付

在 `feature/sample-workstation-http-readonly` 隔离分支提交协议客户端、只读契约/路由和测试。当前工作区的未提交改动不复制、不修改；后续由维护者选择 cherry-pick 或合并。
