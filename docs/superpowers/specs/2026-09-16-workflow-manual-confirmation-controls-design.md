# WPF 流程人工确认操作设计

## 目标

在 WPF“流程运行监控”中完成等待中的 `core.manual-confirmation` 节点，使操作员无需命令行或直接调用 API，即可在设备指令发送前选择继续或取消后续流程。

## 用户交互

运行中存在等待人工确认的节点时，页面顶部显示一条人工确认操作区，内容包括节点名称、确认提示和两个按钮：

- **确认并继续**：确认现场条件满足，释放后续节点。
- **取消本流程**：取消人工节点并沿 `cancelled` 路径结束后续流程。

没有等待人工确认节点时，操作区完全折叠，不占布局空间。按钮提交期间禁用，避免重复点击。

取消只影响尚未执行的工作流步骤，不调用设备远程停止，也不打断已经开始的设备动作。

## 权限

操作复用运行监控页现有“操作者”输入框和 MES 权限校验结果。只有当前操作者已完成权限校验且具备 `workflow.complete-manual-task` 时，两个按钮才可用。

代码不硬编码 `admin`。现场测试可在操作者栏输入具有该权限的账号并点击“校验权限”。

## 组件与数据流

1. `IMesClient` 和 `MesClient` 增加完成人工确认的方法，调用现有端点：
   `POST /api/workflow-runs/{workflowRunId}/nodes/{nodeExecutionId}/manual-confirmation`。
2. `WorkflowRunMonitorViewModel` 从已加载节点中识别等待状态的 `core.manual-confirmation` 节点，并公开操作区可见性、提示、可用性和两个命令。
3. 每次操作生成新的 Request ID；请求包含当前操作者、操作原因、确认结果和可选备注。
4. 成功后立即刷新同一 Workflow Run。`Confirmed` 由现有运行时推进下一节点；`Cancelled` 沿工作流取消分支推进。
5. WPF 不直接调用工作站启动接口；后续设备执行仍由现有 MES worker 单次认领和派发。

## 错误处理

- 无运行实例、无等待人工节点、未校验权限或缺少权限时，按钮禁用并显示原因。
- MES 返回冲突、无权限或其他失败时，保留当前人工节点状态并显示错误。
- WPF 不自动重试人工确认请求；操作员核对状态后可再次主动操作。
- 刷新后如果人工节点已不再等待，操作区自动隐藏，防止对过期节点再次提交。

## 验证

- HTTP 契约测试：校验端点、节点执行 ID、Request ID、操作者、原因和 Outcome。
- ViewModel 测试：等待节点识别、权限门禁、确认、取消、提交中禁用、成功刷新和失败保留。
- WPF 绑定测试：操作区仅在等待人工节点时可见，两个按钮绑定正确。
- 回归测试：运行监控现有权限、暂停、取消、Unknown 处置与自动刷新行为不变。

## 非目标

- 不增加设备远程停止。
- 不自动弹窗或自动确认。
- 不硬编码操作者身份。
- 不自动发现或切换到其他 Workflow Run。
- 不改变 MES 现有人工确认端点或权限模型。
