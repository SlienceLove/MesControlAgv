# 物料管理模块设计

- 日期：2026-09-09
- 状态：待用户审阅
- 范围：第一阶段样品/耗材登记、仓库库存、扫码溯源和实验任务绑定

## 1. 背景与目标

当前项目的实验方案只有 `MaterialRequirements` 快照，实验任务只有自由文本形式的
`SampleId`/`SampleBatchId`。系统还没有样品实体、耗材批次、仓库库位、库存流水或扫码事件，
因此无法回答“某个样品/耗材现在在哪里、被哪个任务预占或使用过、剩余多少”。

本阶段增加一个独立的“物料管理”模块，形成下面的最小闭环：

```text
样品/耗材导入或扫码登记
        -> 仓库/库位库存
        -> 任务准入时校验并预占
        -> 实际进样记录消耗
        -> 按条码、批号或任务查询追溯时间线
```

真实进样器启动/写入接口不在本阶段接入。系统只保存经过校验的样品编号、进样位置和待执行记录，
为后续设备适配预留接口。

## 2. 范围与非目标

### 2.1 本阶段范围

- 样品档案登记、CSV/XLSX 批量导入和扫码查询。
- 耗材/物料主数据、批次、有效期、库位和库存数量。
- 默认仓库下的入库、移库、库存调整、预占、释放和消耗。
- 扫码事件和不可变库存流水。
- 实验任务的样品校验、物料可用量检查和预占。
- 按样品条码、耗材条码/批号、实验任务号查询追溯时间线。
- MES 后端 API、WPF 页面和自动化测试。

### 2.2 明确不做

- 采购、供应商审批、收货质检和完整 WMS 流程。
- 多级仓库组织、自动盘点和复杂角色审批。
- 厂家扫码枪专用协议；第一版使用键盘输入/手工输入兼容方式。
- 对离子色谱或其他进样器发送真实启动、导入、删除等写命令。
- 将仓库字段堆入实验流程编辑器或任务导入表单。

## 3. 领域模型

方案物料要求与实际库存台账分层。`ExperimentPlan.MaterialRequirements` 继续保存方案版本的
需求快照，不能被用作库存余额；现有任务中的 `SampleId`/`SampleBatchId` 保留用于兼容显示。

### 3.1 主数据与库存对象

| 对象 | 第一阶段必要字段 | 规则 |
| --- | --- | --- |
| 物料主数据 | 物料编码、名称、类型（样品/耗材）、规格、单位、启用状态 | 编码唯一；停用不删除历史 |
| 样品档案 | 样品编号/条码、样品批次、样品类型、状态、当前位置 | 按单件或单容器追踪；样品码在样品命名空间内唯一 |
| 耗材批次 | 物料编码、批号、供应商（可选）、生产日期（可选）、有效期（可选） | 批号与物料编码组合定位批次 |
| 仓库库位 | 仓库名称、库位编码、启用状态 | 第一阶段提供默认仓库和可维护的库位文本 |
| 库存余额 | 样品或耗材批次、库位、`onHand`、`reserved`、隔离/过期标记 | `available = onHand - reserved`；隔离和过期不计入可用量 |
| 任务物料绑定 | 实验任务、样品或耗材库存对象、数量、预占状态、进样位置（可选） | 绑定是任务追溯入口，不复制完整物料资料 |

耗材可以按批次+库位计量；若有独立容器条码，条码作为该批次库存对象的解析入口。样品不以大宗
数量计量，每个样品记录独立状态和位置。

### 3.2 审计对象

- **库存流水**：入库、移库、预占、释放、消耗、盘点调整、隔离/解除隔离。流水只追加不修改，
  带操作人、UTC 时间、来源任务、原因和幂等关联号。
- **扫码事件**：原始码、规范化码、扫码类型（样品/耗材批次/容器）、来源（手工/扫码枪/接口）、
  解析结果、操作人和时间。样品码与耗材码按类型分命名空间，避免跨类型碰撞。

## 4. 库存与任务状态规则

1. 入库增加 `onHand`，移库只改变库位，不改变总量。
2. 排程/任务准入时只增加 `reserved`，不扣减 `onHand`。
3. 取消、失败或明确释放时减少 `reserved`，并追加释放流水。
4. 实际进入取样/进样记录节点时，才同时减少 `onHand` 和对应预占量，追加消耗流水，关联任务、
   样品编号和进样位置。
5. 过期、隔离和停用物料不能被新任务预占；可用量不足时任务不能准入。
6. 同一请求重复提交必须返回第一次处理结果，不得重复入账或重复预占。
7. 余额和流水写入在同一个数据库事务中完成；任何调整都必须填写原因，不允许 UI 直接编辑余额。

任务导入阶段允许保存草稿。任务准入/排程时，如果任务带有样品编号，必须解析到已登记且可用的
样品；方案有耗材需求时，必须检查可用量并创建绑定/预占。历史任务不强制回填新关联。

## 5. WPF 页面设计

在现有操作导航中增加与排程同级的一级菜单 **“物料管理”**，页面只保留三个切换页，不新增复杂
的仓库后台：

### 5.1 样品

- 列表展示：样品编号/条码、样品批次、状态、当前位置、绑定任务。
- 操作：新增、扫码登记、CSV/XLSX 批量导入、查看追溯。
- 导入先预览和逐行校验；以样品条码幂等，重复条码显示“已存在”而不重复创建。
- 状态只展示：可用、已预占、使用中、已消耗、隔离/过期。

### 5.2 耗材库存

- 列表展示：物料编码、名称、批号、规格、有效期、库位、可用数量。
- 操作：扫码/手工入库、批量导入、移库、预占/释放、库存调整。
- 导入字段限制为：编码、名称、批号、单位、数量、有效期、库位、条码（条码可选）。
- 调整必须填写原因；页面不提供修改历史流水的入口。

### 5.3 扫码与追溯

- 顶部提供一个扫码输入框，兼容扫码枪键盘输入，也允许手工输入。
- 解析后显示识别类型、当前状态和可执行动作：登记、入库、移库、绑定或查询。
- 支持按样品条码、耗材条码/批号、任务号查询时间线：登记 → 入库 → 移库 → 预占 → 使用/消耗。
- 时间线只读；未知码、重复码、过期/隔离码显示明确原因和下一步建议。

实验任务和任务导入页面只展示“样品编号 + 物料校验结果”，不显示仓库流水字段。校验成功后由
后端建立预占；进样器暂不发送写命令。

## 6. 后端边界与接口分组

MES 是物料数据和规则的唯一来源，WPF 不直接访问数据库。接口按能力分组，避免为每个页面动作
暴露过多细碎端点：

- **查询**：样品、物料/批次、库存余额、追溯时间线。
- **导入**：上传样品或耗材文件，返回预览错误；提交通过的行。
- **扫码**：提交原始码和扫码类型，返回解析对象及允许动作。
- **库存命令**：入库、移库、库存调整、预占、释放、消耗。
- **任务绑定**：按实验任务绑定样品/库存对象并返回校验结果。

所有写请求携带请求号/关联号。重复请求返回原结果；余额不足、未知条码、库位不存在、状态冲突、
导入行错误等情况返回可显示的业务错误，不返回“成功但未入账”。

## 7. 数据库升级与兼容

- 新表与既有实验表分开增加，启动升级只执行幂等的建表/索引操作，不删除或重写历史实验数据。
- 关键唯一性：物料编码、样品条码（按类型）、批次+物料、库位编码和请求关联号。
- 现有 `MaterialRequirementsJson`、`SampleId`、`SampleBatchId` 字段保持不变；新任务可额外保存真实
  样品/库存引用，旧数据按原逻辑读取。
- 初始化一个默认仓库；库位和物料必须由用户登记或导入后才可用于新任务。

## 8. 验证与验收

### 8.1 自动化验证

- MES 领域测试：入库、移库、预占/释放、消耗、隔离/过期和可用量不变量。
- 幂等/并发测试：重复扫码、重复导入、重复预占和余额冲突。
- HTTP 契约测试：导入预览/提交、扫码解析、库存命令、追溯和任务绑定。
- WPF 测试：导入预览、逐行错误、扫码结果、库存操作反馈、任务准入校验。
- 旧数据库启动升级测试：新版本启动后既有实验计划、任务和审计数据仍可读取。

### 8.2 手工验收路径

1. 导入一条样品和一批耗材，确认列表和扫码查询均可找到。
2. 扫码耗材入库并移到另一库位，确认余额总量不变、时间线有两条流水。
3. 创建带样品和耗材需求的任务，确认可用量检查和预占数量正确。
4. 取消任务，确认预占释放且不产生错误扣减。
5. 记录一次待进样样品的使用，确认生成消耗流水，但没有向进样器发送写命令。
6. 重复提交同一导入/扫码请求，确认结果幂等且库存只变化一次。

## 9. 后续扩展边界

后续接入真实扫码设备、进样器启动接口、容器拆分/合并、供应商和审批流程时，均通过现有扫码、
库存命令和任务绑定接口扩展，不改变本阶段的流水和追溯语义。
