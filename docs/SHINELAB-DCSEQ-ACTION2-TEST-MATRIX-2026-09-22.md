# DCSeq action=2 受控实测矩阵（2026-09-22）

## 目的

根据`res/鲲达自动化-物联系统-对接工作安排-讨论版.docx`，确认`Command action=2`究竟停止当前样品还是整个序列，并记录客户端生命周期消息的真实顺序。
本测试不把协议表中尚未观测到的字段当作已实现行为。

## 前置条件

- 仅保留一个明确测试样品；确认AQ当前序列、样品位置、方法和自动接续设置。
- 设备已认证，`STN61_01`对应连接稳定；测试前记录`Device`状态和TCP连接。
- 先完成一次Config并现场确认样品确实进入目标序列；Config成功本身不作为样品落地证明。
- 测试前保存任务UUID、sampleId、序列名称、Config响应和最近状态快照。
- 不使用真实危险样品；空位或经现场确认的安全样品由操作员决定。

## 执行步骤

1. 由操作员启动单条样品，确认收到`Device/UpdateInfo status=1`或等价运行状态。
2. 在样品尚未自然结束时，由中控仅发送一次`Command action=2`，保存完整请求、响应、strID和收发时间。
3. 观察至少一个`StatusStaleAfter`窗口，记录：
   - 当前样品是否停止，泵/进样器/序列运行状态是否变化；
   - 队列中下一条样品是否自动开始；
   - 是否收到`SampleFinish`、`TaskFinish`、`Result`、`EndMission`、`TaskError`，以及每条消息的sampleId/taskUuid/finishDate；
   - 是否出现重复上报、空sampleId或只带数字sampleId。
4. 若action=2只停止当前样品且队列继续，立即记录下一条是否已开始；不要再次发送停止命令，避免混淆范围。
5. 若action=2停止整个序列，记录队列剩余数量和AQ界面状态；不要补发Command=0。
6. 测试结束由操作员在AQ确认仪器安全状态，再断开连接或清理测试序列。

## 判定规则

| 观察结果 | 结论 |
| --- | --- |
| 当前样品停止，下一条自动开始 | action=2为当前样品停止，或客户端将停止后续任务策略交给序列调度；需结合队列日志确认 |
| 当前样品停止，队列保持停止 | action=2至少影响当前运行序列；是否清空队列需另测 |
| 当前样品继续运行 | action=2可能仅被接受未执行，或需要特定任务字段；记录响应与Device变化，不判定成功 |
| 仅收到Success，无状态变化 | Success只是请求接受，不代表动作完成 |
| 收到SampleFinish但无Result | 不能判定分析结果完成；保留为生命周期观察 |
| 收到TaskFinish/EndMission | 结合队列和序列状态判断是单条还是整序列，不能仅凭消息名称推断 |

## 必留证据

- action=2完整JSON、响应JSON、请求/响应strID；
- 发送前后所有Device/UpdateInfo和生命周期消息原文；
- AQ序列列表、当前样品、队列状态截图；
- MES接收UTC时间与报文中的设备时间分开记录；
- 测试前后任务记录和`push-evidence`查询结果。

## 安全边界

本矩阵只授权一条受控测试样品和一次action=2。未得到现场操作员明确确认前，不发送Config、Command或自动重试；出现异常时由操作员在AQ侧手动停止。
