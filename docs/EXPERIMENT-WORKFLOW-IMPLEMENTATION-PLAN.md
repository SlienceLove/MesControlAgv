# 实验流程编排实施计划与验收门禁

> 状态：G2-B 已实现，等待主编辑器 Nodify 接入验收；G2-C 尚未开始
> 日期：2026-08-20
> 关联：[目标架构](EXPERIMENT-WORKFLOW-ARCHITECTURE.md)、[界面规划](EXPERIMENT-WORKFLOW-UI-DESIGN.md)、[画布技术评估](EXPERIMENT-WORKFLOW-CANVAS-EVALUATION.md)

## 1. 执行原则

本计划将实验流程模块拆成可独立验收的阶段。每个阶段完成后停止推进后续阶段，提供代码变更、自动化测试结果、手工验收步骤和遗留风险，由项目方确认后再开始下一阶段。

- 不通过 WPF 直接访问 AGV、机械臂或仪器协议。
- CIC-D160+ 在所有阶段保持只读；任何写入能力需要独立现场安全证据和明确授权。
- 在 Nodify Spike 通过前，不将其绑定为不可替换的正式 UI 框架。
- 流程定义、排程、运行实例和设备操作始终保持不同职责，不以画布模型替代运行模型。
- 抓包计划、旧抓包分析和与流程无关的工作区改动不纳入本计划的提交范围。

## 2. 阶段总览

| 阶段 | 交付目标 | 用户验收节点 | 通过后才进入 |
| --- | --- | --- | --- |
| 0 | 范围、架构和门禁确认 | G0：确认实施顺序和安全边界 | 阶段 1 |
| 1 | 统一流程文档雏形和 Nodify 画布 Spike | G1：确认继续使用 Nodify 或启动替代框架评估 | 阶段 2 |
| 2 | 单一流程定义、编辑器收敛和版本往返 | G2：确认设计器可以承载受控草稿/发布 | 阶段 3 |
| 3 | 类型化节点、能力目录和发布校验 | G3：确认错误配置无法进入发布版 | 阶段 4 |
| 4 | 节点执行记录和只读运行监控 | G4：确认运行状态和恢复证据一致 | 阶段 5 |

## 3. G0：计划确认

### 本阶段交付

- 目标架构、界面规划和画布技术评估文档。
- 本实施计划和全部验收门禁。
- 当前 WPF 双流程编辑模型、MES 生命周期接口和设备安全边界的盘点。

### 验收标准

- 认可 `ExperimentPlan`、`ExperimentJob/ScheduleEntry`、`WorkflowRun` 三者分离。
- 认可流程节点只引用设备能力，不携带寄存器地址、原始报文或厂商命令。
- 认可第一阶段只做隔离 Spike，不连接真实设备写接口。
- 认可 Nodify 只作为可替换画布候选，不能被视为流程引擎。

### 通过后的动作

开始阶段 1；不修改现有生产工作流运行行为。

## 4. G1：统一文档与 Nodify Spike

### 实现范围

1. 新增独立的共享流程定义模型，至少包含节点、显式边、端口、布局和 schema 版本；以新增类型和适配器方式接入，不破坏现有 HTTP 契约。
2. 定义 WPF 内部 `IWorkflowCanvasSurface`，由 `NodifyCanvasAdapter` 将画布事件转换为编辑命令；Contracts、Domain、MES 和设备工程不引用 Nodify 类型。
3. 在隔离的 WPF Spike 中实现并验证：节点创建/移动、端口连线、连接规则、编辑历史、子图复制粘贴、布局往返、校验定位和只读运行态覆盖。
4. 使用 20 节点/19 边、60 节点/90 边和 200 节点/350 边三组内存样例；500 节点仅作探索性压力测试。

### 自动验收

- 新模型和编辑命令的单元测试覆盖 ID 重写、边语义、非法连接拒绝、保存/加载和 100 次撤销/重做往返。
- Release 构建无新增警告或错误。
- 现有 MES、Adapter、InstrumentGateway 和 WPF 测试保持通过。
- 200 节点/350 边样例加载不超过 2 秒，记录加载时间、内存和交互观察结果。

### 手工验收

1. 打开隔离 Spike，不连接 MES 写接口或真实设备。
2. 创建 AGV 移动、机械臂程序、仪器读取、等待和条件节点。
3. 验证非法端口连接被拒绝并显示原因；成功、失败、超时和条件边具有明确标签。
4. 复制一组 5 节点/6 边子图，确认新节点和边的 ID 独立且连接正确。
5. 连续编辑、撤销 100 次、重做 100 次，点击 `JSON 往返`，确认重新加载后的流程定义等价。
6. 切换编辑和只读运行态，确认状态标记不改变定义内容或节点位置。

### 决策门禁

| 结果 | 用户确认项 | 后续动作 |
| --- | --- | --- |
| 所有验收通过 | G1 通过，继续 Nodify | 进入阶段 2 |
| 只有历史、剪贴板或布局需要自建 | 确认可接受自建编辑服务 | 保留 Nodify，进入阶段 2 |
| 性能、状态覆盖或基础交互不达标 | 确认启动商业 Diagram 评估 | 保留模型和适配接口，不进入阶段 2 |

### G1 交付记录

代码、自动化结果、性能测量、手工步骤和待确认决策见
[G1 验收记录](EXPERIMENT-WORKFLOW-G1-ACCEPTANCE.md)。在项目方确认前，不进入 G2。

## 5. G2：编辑器收敛与版本往返

### 实现范围

- 将现有 `ExperimentFlowEditorViewModel` 和 `WorkflowEditorViewModel` 收敛为单一流程文档 ViewModel。
- 保留 MES 的 Draft、Validate、Publish、DryRun 生命周期，通过适配器读写统一定义。
- 旧 `ExperimentFlowConfigDto` 只保留导入转换；新流程只写新格式。
- 将独立流程设计器接入主窗口，移除双模型同时编辑同一业务流程的路径。

### 验收标准

- 同一流程可编辑、保存草稿、重新加载、校验、发布和查看版本，节点、边、端口、参数和布局无丢失。
- 任一旧格式导入都生成明确转换报告；不能转换的内容不得静默丢弃。
- 发布版本不可由画布直接修改；运行请求固定到明确版本。
- 用户确认：设计器已可替代旧的业务编辑入口。

### G2 当前执行记录（2026-08-19）

G2-A 已完成文档/契约收敛：新增 Graph Document 与 MES 合同适配器，WPF 本地存储改为 `mes.workflow.graph` 信封格式，旧 WPF JSON 仅作为导入格式；历史 Nodify 编辑器的导出也改为 Graph Document。MES Draft、Validate、Publish、Version 和 DryRun HTTP 路径保持不变，运行请求仍固定到明确版本，未开放任何设备写操作。

G2-A 验收记录见 [EXPERIMENT-WORKFLOW-G2-ACCEPTANCE.md](EXPERIMENT-WORKFLOW-G2-ACCEPTANCE.md)。主窗口 Nodify 画布替换和旧 WPF 可观察投影的最终移除留在下一验收节点，避免在未确认前一次性破坏现有绑定。

### G2-B 当前执行记录（2026-08-20）

主窗口手工 Canvas 已替换为 `NodifyCanvasAdapter`，并通过 `IWorkflowCanvasSurface` 保持框架可替换边界。画布选择、右侧属性、节点参数、拖放新增、移动、显式连线、删除、撤销/重做、自动布局、适应画布和视口持久化均落到同一个 `WorkflowGraphDocument` 编辑历史；视口变化不污染撤销栈。

Graph Document schema 已提升到 v2：仅 v1 Graph Document 和旧 WPF 数组在整图完全无边时补顺序成功边，v2 断开草稿保持断开。默认预置流程直接保存 6 节点、5 条显式边和兼容运行时所需的 `NextNodeIds`。Release 全方案构建为 0 警告/0 错误，全量测试 570 通过、5 个既有 E2E 跳过、0 失败；隔离 Simulator 主窗口冒烟确认 `节点 6 / 边 5` 且连线和属性面板正常渲染。

G2-B 的手工验收步骤和剩余边界见 [EXPERIMENT-WORKFLOW-G2-ACCEPTANCE.md](EXPERIMENT-WORKFLOW-G2-ACCEPTANCE.md)。验收前不进入 G3。G2-C 仅收口旧 `实验流程设计` 入口、WPF 兼容投影所有权和可见的旧格式转换报告，不扩展设备执行能力。

## 6. G3：类型化节点与发布校验

### 实现范围

- 建立设备能力目录和节点 schema 版本。
- 首批节点：Start、End、AGV 到站、定时等待、人工确认、仪器读取、仪器稳定等待。
- 右侧属性面板按 schema 显示站点、设备、能力、超时、重试和安全等级，而不是自由键值参数。
- 发布前校验能力/Profile、站点存在性、端口基数、异常边和必填配置。

### 验收标准

- 无效站点、未知设备、未启用能力、未配置超时或缺少默认路径的流程不能发布。
- D160 只显示已验证的只读能力；写入能力显示为不可用且不能绕过。
- 点击每条校验问题可定位到对应节点或边。
- 用户确认：第一批实验步骤可以无协议细节地配置。

## 7. G4：运行记录与只读监控

### 实现范围

- 引入 `NodeExecution`、`DeviceOperation` 和运行时间线，替换单一 `PendingStep` 作为内部恢复依据。
- 将现有 AGV Move 和定时等待迁移为统一节点执行器；继续保持现有外部读取兼容。
- 实现只读运行画布、节点详情、设备操作证据、暂停/恢复/取消和 Unknown 处理入口。

### 验收标准

- MES 重启后能从节点执行记录恢复并显示一致的当前状态。
- 每次设备操作有请求 ID、操作 ID、结果、证据摘要和重试/人工处理记录。
- 运行画布不会更改已发布定义；危险操作具有权限、理由和审计。
- 用户确认：运行人员可以判断流程为何停留、谁处理过以及下一步可做什么。

## 8. G5：方案、排程与资源租约

### 实现范围

- 引入 `ExperimentPlan`、`ExperimentJob/ScheduleEntry` 和 `ResourceLease`。
- 支持任务池、计划时间、优先级、资源可用性和阻塞原因。
- 在运行准入时获取资源租约，任务完成、取消或恢复失败后按策略释放。

### 验收标准

- 两个运行不能同时持有同一 AGV、机械臂、仪器或互斥工作站资源。
- 看板显示资源负载、计划时间和阻塞原因；调度不直接推进流程节点。
- 资源占用、释放和人工干预均有审计。
- 用户确认：能安排多项实验且能解释每项任务的状态。

## 9. G6：高级流程与受控设备能力

### 实现范围

- 结构化条件、信号等待、人工任务、补偿边、并行分叉/汇合和可复用子流程。
- 设备控制能力仅在协议验证、现场安全评审、权限策略和故障恢复方案均完成后逐项开放。

### 验收标准

- 条件和人工任务均可追溯其输入、决策和处理人。
- 并行执行、资源租约和恢复策略在故障注入测试中保持一致。
- 每项设备写能力都有独立的现场验收记录；D160 写入不因本计划自动开启。
- 用户确认：高级语义适合实际实验 SOP，且异常路径可安全处理。

## 10. 每个验收包的固定内容

每个 G1-G6 验收节点均提供以下内容，作为继续下一阶段的依据：

1. 本阶段变更清单和未做事项。
2. 构建、单元测试和必要的集成测试结果。
3. 可复现的手工验收步骤及预期现象。
4. 关键界面截图或可运行入口（适用时）。
5. 风险、兼容性影响和回退方法。
6. 明确的“通过/需修改/改选框架”确认问题。

未得到验收确认时，只修复该阶段问题，不开始下一阶段的功能。
