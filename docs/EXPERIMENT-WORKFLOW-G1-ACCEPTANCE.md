## 1. 本次结论

G1 已完成一个与 MES、AGV、机械臂和仪器控制隔离的 Nodify 画布 Spike。
当前建议是：**保留 Nodify 作为 G2 的可替换画布候选，等待项目方完成下列手工验收后再进入 G2。**

这不是把 Nodify 定为流程引擎，也不是批准任何设备控制能力。流程图定义、编辑历史和连接规则由共享 Contracts/Domain 模型负责；Nodify 只存在于 WPF 适配层，可在后续替换为其他 Diagram 控件。

## 2. 已交付内容

- 新增版本化 `WorkflowGraphDocument`，包含节点、显式边、端口、端口基数、边语义、节点配置、布局与视口状态。
- 新增框架无关的 `WorkflowDocumentEditor`：节点和边编辑、批量位置提交、撤销/重做、子图复制粘贴、JSON 往返与可替换分层布局。
- 新增领域连接策略：校验节点/端口存在性、输入输出方向、精确数据类型、目标端口基数、重复边，以及源端口的成功/失败/超时/条件语义。
- 新增 WPF 内部 `IWorkflowCanvasSurface` 和 `NodifyCanvasAdapter`；Contracts、Domain、MES、Adapter、InstrumentGateway 不引用 Nodify。
- 新增隔离窗口与启动参数 `--workflow-canvas-spike`。该分支在常规服务启动之前执行，只创建内存中的画布样例。
- 提供 `20/19`、`60/90`、`200/350` 和 `5/6` 复制探针四组内存数据；工具箱包含 AGV 到站、机械臂程序、仪器读取、等待和条件节点。
- 提供编辑、只读、运行态覆盖三种模式；运行态覆盖不修改定义、位置或任何设备状态。

本次没有改动既有 MES 工作流 HTTP 契约、发布路径、运行工作器或任一设备协议路径。

## 4. 项目方手工验收

先构建并启动隔离入口：

```powershell
dotnet build src\MesControlAgv.Wpf\MesControlAgv.Wpf.csproj -c Release --no-restore
.\src\MesControlAgv.Wpf\bin\Release\net8.0-windows\MesControlAgv.Wpf.exe --workflow-canvas-spike
```

验收时确认以下现象：

1. 标题为“实验流程画布 Spike”，副标题明确显示“仅使用内存样例”，且没有启动常规 MES 页面或设备控制入口。
2. 分别加载线性 `20/19`、分支 `60/90` 和压力 `200/350` 样例；观察节点、边标签和画布缩放/平移是否流畅。
3. 从工具箱添加 AGV 移动、机械臂程序、仪器读取、等待和条件节点，拖动节点后执行撤销与重做。
4. 从成功、失败、超时和条件端口分别创建边，确认边标签与源端口语义一致；尝试输入到输出、重复边或已占满的单输入端口，确认右侧显示拒绝原因。
5. 选择“复制 `5/6`”样例，框选全部节点后复制、粘贴；确认新增节点和内部边都存在且与原图独立。
6. 连续调整同一节点位置并撤销、重做，点击 `JSON 往返`；确认提示说明仅在内存中往返，且节点、边和位置保持不变。
7. 切换 `Edit`、`ReadOnly`、`Runtime`，确认只读模式无法新建连接，运行态标签不移动节点或改变边。
8. 点击右侧 `SPIKE-CONNECTION-POLICY` 问题，确认画布定位到对应节点。

## 5. 风险与非目标

- Nodify 提供基础节点画布能力，但撤销/重做、复制粘贴、图布局、校验定位和业务连接规则由本项目维护；这一维护成本已显式保留在 G2 以后评估中。
- 当前样例证明 200 节点/350 边可用，不代表复杂子流程、泳道、BPMN、版本差异审阅或无限大图已经满足需求。若这些成为明确需求，应在 G1 决策时启动商业 Diagram 控件评估。
- 画布当前只读写内存文档。它不保存到 MES，不创建运行实例，不获取资源租约，不执行 AGV、机械臂或仪器操作。
- CIC-D160+ 继续保持只读边界；本 G1 不改变任何串口、网关、HTTP 或工作器写入能力。
