# WPF 标准流程界面问题补充记录（2026-09-02）

本记录对应现场提供的运行监控截图，当前仅记录，不在本次实体流程重跑期间修改界面。

## 问题 4：运行图与阶段信息区域过小

- 流程运行图区域高度不足，节点/连线无法有效查看。
- 当前阶段、当前节点、进度和运行信息被挤压在狭窄区域，文字难以阅读。
- 后续修复方向：为运行图设置合理的最小高度，阶段/进度信息独立布局，必要时增加滚动或缩放能力，并验证窗口尺寸变化下的可读性。

## 处理约束

- 本问题与程序目录刷新卡顿、程序列表缺少滚动查看问题合并到本次完整流程结束后的 UI 修复批次。
- 当前现场会话不调整 WPF 布局，避免影响正在使用的运行监控和审计记录。

## 问题 5：手动速度倍率切换 Automatic 后恢复为 100%

- 现场将 AUBO 手动模式速度倍率调为 30%，切回 Automatic 后显示恢复为 100%。
- 这表明手动模式倍率与自动运行倍率不是同一设置，当前 WPF/MES 没有显示或写入自动模式速度倍率的接口。
- 后续处理方向：确认 AuboStudio 自动模式“运行屏幕/速度调节条”是否启用；评估为三个批准工程配置持久化的“初始速度比例”，并在 WPF 显示实际生效倍率。
- 未经厂家确认前，不通过 Modbus 寄存器或未验证 RPC 强行写入速度参数。

### 现场临时处置记录

- 已由现场人员启用 AuboStudio Automatic 模式速度调节条，并将当前速度比例设为 `30%`。
- WPF/MES 当前只能读取机器人模式、安全状态、运行态和工程名，不能回读该速度倍率；后续程序执行前以示教器实时显示为准。

## 收尾修复（2026-09-02）

- 问题 1：Adapter 的只读程序目录扫描增加 `ProgramCatalogScanTimeoutMs`（现场配置 5000 ms），并在 WPF 请求开始时立即显示“正在读取控制器程序目录…”。超时只返回部分只读证据，不会触发重连、写入或自动重试。
- 问题 2：程序目录区域移动到 AUBO 响应面板顶部，列表固定可视高度并启用垂直滚动，右侧面板增加滚动容器；现场确认的三个 `.pro` 名称可完整选择。
- 问题 3：PhysicalAcceptance 源配置已将 `ARM-01` 的 `controlEnabled` 设为 `true`，并补齐 `admin` 的暂停、取消、Unknown 处理、信号提交和人工完成权限。worker 与自动派发仍保持关闭，控制不会因启动配置而自动执行。
- 问题 4：运行监控画布行增加最小高度，节点表改为剩余空间布局，当前节点文本允许换行；运行画布首次加载时自动适配内容，避免历史视口把流程压缩成细条。
- 问题 5：本次不改动速度写入接口；30% 仍以现场 AuboStudio Automatic 运行屏幕为准，WPF/MES 继续只读展示。

完整现场运行收尾记录见：[material-wpf-20260902-final-run.md](physical-acceptance/material-wpf-20260902-final-run.md)。

## 下一阶段目标：标准模板一键现场执行

为避免恢复现场后逐段点击，已补充一键执行能力，但保持双重门禁：WPF 只有在
`WPF_ENABLE_PHYSICAL_BATCH=true` 且选择已发布料盘标准模板时显示按钮；MES 只有在
`WorkflowFieldNavigationWorker.Enabled=true`、`AutoAuthorizeFromRunRequest=true`、
现场导航功能和 AUBO worker 均显式启用时，才会根据运行请求自动生成逐段许可。每段
仍会重新读取 AGV 当前站点/任务状态并通过原有 Adapter 物理预检，异常不会自动重试。

当前签入配置不打开这些物理批量开关；本能力已在隔离单元测试中验证，现场启用必须
在新的只读预检、总授权和维护变更后进行。

## 全屏查看补充（2026-09-02）

后返回原页面。全屏镜像不会停止主页面的自动刷新，也不会发出任何设备控制请求。新版 WPF 已
