# AGV 自动重定位接口评估记录

日期：2026-09-03（Asia/Shanghai）

## 本次结论

现场 Roboshop 控制软件存在“自动重定位”按钮，说明控制器或其上位机具备该能力；但当前仓库尚未取得该按钮对应的真实请求/响应证据，因此暂不绑定任何重定位写命令。

当前已确认：

- TCP API `1021` 是只读定位状态查询；`reloc_status=1` 才表示定位已被控制器接受，状态 `3` 仍需人工确认。
- 当前 Adapter 没有已验证的 `RelocalizeAsync` 写接口，也不会在预检、刷新或普通派发路径中发送重定位命令。
- 协议测试中的 API `2002` 仅验证了厂家示例报文格式（`x/y/angle`），尚未确认现场坐标来源、单位、坐标系、完成响应及是否需要 `2003/2004` 后续确认。
- 不允许直接使用 AGV 当前上报位姿回写重定位；坐标语义未确认时可能写入错误位置。

## 网络恢复后的确认步骤

1. AGV 停稳、无活动任务、无障碍，保持人工监护，不运行生产流程。
2. 使用 Roboshop 手动点击一次“自动重定位”。
3. 在隔离现场网络抓取该次操作的接口编号、端口、请求载荷、响应和状态变化。
4. 确认完成条件（`reloc_status`、置信度、人工确认要求和超时语义）。
5. 仅在证据完整后实现独立的 `RelocalizeAsync`，默认关闭并保留人工确认/审计。

## 预期运行策略

当定位置信度低于 `0.90` 时，流程先暂停并提示；协议确认后才允许每个流程阶段最多触发一次重定位，完成后重新读取定位状态并要求置信度稳定恢复。超时、急停、阻挡、故障或需要人工确认时保持暂停，不自动无限重试。
